# 系统架构与核心机制

## C# 与 DV

`core/dv` 解析 DV 声明与类型化历史，`core/reasoning` 提供推理、证明检查、有限模型和规划，`core/runtime` 持有世界、人物认知、行动、调度及空间生命周期。三个库不依赖 Godot。`core/cli` 将 Runtime 适配为正式文本宿主。

依赖方向为 `CLI → Runtime → Reasoning → DV`，Runtime 同时直接引用 DV。根 Godot C# 工程通过 ProjectReference 使用这些库，只编译 `scenes/**/*.cs` 中的宿主桥接代码，避免重复编译库源码。解决方案默认构建涵盖 Godot 与 CLI。

人物、初始状态、世界规则、行动、动机参数、章节及五日观察窗由 `assets/data/scenarios/campaign.dv` 与其 DV 来源声明。宿主不另行实现这些规则。CLI 保留正式内容的完整人物关系；角色模型预览清单不改变推演人口。

## 自主决策与证据

客观世界事实与各人物的已知事实、来源证据独立保存。行动候选、条件判断及规划依据使用人物本人所知；决定后仍由权威世界检查和提交真实结果。需要变化、职责偏好、行动代价、失败记忆和目标规划共同影响选择。

正式 CLI 自动入口让引擎决定所有人物的行动。AI／人工输入入口接收玩家选择，其余人物继续自主调度。连续运行推进声明的游戏时间，内容定义观察终点和阶段。第五日的自主观察阶段关闭任务引导，继续保留个人需要、已知条件和行动约束。

每次实际行动将候选评分、需要贡献、行动意图、本人认知依据、实际效果与结果写入宿主审计回执。审计数据供作者检查，可包含人物私人认知，不作为玩家界面可随意读取的投影。内容重载由 Runtime 的版本迁移接口保留状态与认知证据；初始布置或初始认知变更要求新局。

## Godot 与美术资源

Godot 正式入口为 `scenes/main/Main.tscn/.gd`，Main 持有 C# `LifeBridge` 和建筑器实例。生活会话使用 `CharacterSessionDefinition`、`RuntimeSession`、既有 Drive 调度及空间生命周期；GDScript 只处理界面、AStar 导航、输入和表现，按实际 Core 时间上报路径进度与到场。关闭生活覆盖层后恢复同一个建筑器。

`LifeScenario` 将生活 DV、正式人物动机和建筑候选编译为普通 Core 行动与规则；`RuntimeLife` 负责库存守恒、实际感知、八种回应、可检验承诺、需要效果和有向关系。`RuntimeLifeSeating` 使用既有预约管理器预留座位，双方正式行动到场并共同停留后才结算履约；让位通过单槽交接释放原占用者。对话双方的社交预约排除重叠互动，非睡眠日常工作可在答复前继续；接受停止噪声后才中断演奏。关系按日额度、同类习惯化、饱和、衰减与阶段滞回更新。所有数值、人口与生活适配偏好来自 DV。

客观库存与可感知库存分开；人物仅在同房观察家具、可见持有物与活动，决策使用本人证据，实际交付在提交侧重检。作者检查器可查看私人需要及权威关系；它不属于人物可知投影。库存、承诺、座位约定、关系、债务、随机状态与证据都进入正式 Runtime 存档。内容重载先检查声明兼容性，在替换前验证保存状态一致，不兼容初值或规则要求新局。

生活新局声明位于 `assets/data/scenarios/life_simulation.dv`，与原 campaign 并存。当前建筑通过候选 DV 加载，正式资源需明确发布。空间范围为首个有封闭房间的单层；模型仍显示原姿态。

`scenes/components/characters/ModelCatalog.cs` 通过 C# DV 解析器读取 `assets/data/character_models.dv`；`CharacterModel.tscn/.gd` 载入清单指定模型并按声明统一高度和朝向。GLB 保留网格、内嵌纹理、蒙皮、骨骼与原动画资源。

`tools/characters/CharacterGallery.tscn/.gd` 提供五人模型预览和旋转。建筑器以覆盖层打开预览，关闭时释放覆盖层并保留建筑编辑数据。模型预览不创建游戏会话或计算动机。

## 构建与宿主入口

项目采用 Godot .NET 4.7.2 与 .NET 8，VSCode 默认构建使用正常 MSBuild 增量检查、并行构建和共享编译。Core 产物位于 `.runtime/build/`，Godot 托管产物由 SDK 管理于 `.godot/mono/`。

`mcp/game` 保留 environment、auto 与 input 协议。CLI 自动运行包含构建与内容验证，保持连接到结束或配置的墙钟截止时间。每个运行持有独立程序集输出，源码和输出哈希均符合才复用已验证构建；游戏状态不缓存，始终开启新局。Godot 游戏会话的接线范围与当前验收状态见 `33 实施与验收.md`。
