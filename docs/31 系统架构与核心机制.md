# 系统架构与核心机制

## C# 与 DV

`core/dv` 解析 DV 声明与类型化历史，`core/reasoning` 提供推理、证明检查、有限模型和规划，`core/runtime` 持有世界、人物认知、行动、调度及空间生命周期。三个库不依赖 Godot。`core/cli` 将 Runtime 适配为正式文本宿主。

依赖方向为 `CLI → Runtime → Reasoning → DV`，Runtime 同时直接引用 DV。根 Godot C# 工程通过 ProjectReference 使用这些库，只编译 `scenes/**/*.cs` 中的宿主桥接代码，避免重复编译库源码。解决方案默认构建涵盖 Godot 与 CLI。

人物、初始状态、世界规则、行动、动机参数、章节及五日观察窗由 `assets/data/scenarios/campaign.dv` 与其 DV 来源声明。宿主不另行实现这些规则。CLI 保留正式内容的完整人物关系；角色模型预览清单不改变推演人口。

## 自主决策与证据

客观世界事实与各人物的已知事实、来源证据独立保存。行动候选、条件判断及规划依据使用人物本人所知；决定后仍由权威世界检查和提交真实结果。需要变化、职责偏好、行动代价、失败记忆和目标规划共同影响选择。

正式 CLI 自动入口让引擎决定所有人物的行动。AI／人工输入入口接收玩家选择，其余人物继续自主调度。连续运行推进声明的游戏时间，内容定义观察终点和阶段。第五日的自主观察阶段关闭任务引导，继续保留个人需要、已知条件和行动约束。

每次实际行动将候选评分、需要贡献、行动意图、本人认知依据、实际效果与结果写入宿主审计回执。审计数据供作者检查，可包含人物私人认知，不作为玩家界面可随意读取的投影。内容重载由 Runtime 的版本迁移接口保留状态与认知证据；初始布置或初始认知变更要求新局。

## Godot 与美术资源

Godot 正式入口为 `scenes/main/Main.tscn/.gd`，Main 持有 C# `LifeBridge` 和建筑器实例。生活会话使用 `CharacterSessionDefinition`、`RuntimeSession`、既有 Drive 调度及空间生命周期；GDScript 只处理界面、AStar 导航、输入和表现，按实际 Core 时间上报路径进度与到场。关闭生活覆盖层后恢复同一个建筑器。

`LifeScenario` 将生活 DV、正式人物动机和建筑候选编译为普通 Core 行动与规则；`RuntimeLife` 负责库存守恒、实际感知、六种回应、可检验承诺、需要效果和有向关系。`RuntimeLifeSeating` 使用既有预约管理器预留座位，双方正式行动到场并共同停留后才结算履约；让位通过单槽交接释放原占用者。对话双方的社交预约排除重叠互动，非睡眠日常工作可在答复前继续；接受停止噪声后才中断演奏。关系按日额度、同类习惯化、饱和、衰减与阶段滞回更新。所有数值、人口与生活适配偏好来自 DV。

客观库存与可感知库存分开；柜内库存通过打开柜子或备餐的实际行动获知。人物在同房、有照明的条件下感知家具；Godot 中人物视觉还受声明的距离限制。可见携粮只投影为布尔片段，不公开数量；声响只投影为当前听觉片段，不公开声源人物和预计结束时间。实际交付在提交侧重检。作者检查器可查看私人需要及权威关系；它不属于人物可知投影。库存、承诺、座位约定、关系、债务、随机状态与证据都进入正式 Runtime 存档。内容重载先检查声明兼容性，在替换前验证保存状态一致，不兼容初值或规则要求新局。

### 主观认知演算

`ActorCognition` 在人物的正式认知更新中接入 `core/reasoning` 的 `CaseTheory`、`CaseInferenceWork` 和独立证明检查器。生活认知理论、感知字段、片段、输入命题、问题、社交认知条件与验收边界由 `assets/data/life_simulation/cognition.dv` 声明。理论禁止预装作者事实；输入只能取本人认知中的非推论字段，不能读取世界或其他人物的心智。初始信念与获得的观察、交流证据保留来源区别。

演算采用有限、无函数、带显式否定的 Horn 逻辑，支持变量统一、多步规则闭包、正反证明和证据追溯。结论状态分别为 `proved`、`refuted`、`conflicted`、`unknown`；没有证明不会生成否定，矛盾不会证明无关命题。可能解释是单独命题：听到演奏声可同时支持“可能在练习”和“可能寻求陪伴”，不能确定真实动机；声源归因另需当前看见演奏动作。空手可以支持尝试询问，不能推出没有储备或确实饥饿。

相关输入变化后，以当前主观证据重建推理闭包，重新发布全部声明问题，因而旧推论可以退回未知或出现反证。历史证据保留用于审计，当前证明只引用现行输入对应的证据；旧推论不能作为自身的新前提。推理按操作数和墙钟片段分步执行，未完成时不发布半截证明，预算耗尽显式报错。它不等同于无限逻辑完备、自然语言通用理解或已验证的人格涌现。

片段接收记录最后感知状态，相同片段在忙碌和认知更新期间不逐帧入队；发生变化后才追加证据。该感知前沿、未处理观察、当前更新、主观事实及完整证据都进入存档；恢复未完成的证明搜索时，从保存的同一批主观输入重新计算。人物认知时间戳保留实际重新观察时间，世界规则的事实变更语义独立。

请求口粮、尝试分享和投诉的认知门槛使用本人的推论，进入正式决策依据审计。世界只在行动提交侧检查真实能力和结果。回应评分保留在作者审计，人物只接收对话表现与实际兑现结果。作者面板显示主观问题状态；完整证明证书和前提证据写入正式 CLI 状态日志，可通过 Main 的 `LifeBridge.InspectCognition` 只读检查。

生活新局声明位于 `assets/data/scenarios/life_simulation.dv`，与原 campaign 并存。当前建筑通过候选 DV 加载，正式资源需明确发布。空间范围为首个有封闭房间的单层；模型仍显示原姿态。

`scenes/components/characters/ModelCatalog.cs` 通过 C# DV 解析器读取 `assets/data/character_models.dv`；`CharacterModel.tscn/.gd` 载入清单指定模型并按声明统一高度和朝向。GLB 保留网格、内嵌纹理、蒙皮、骨骼与原动画资源。

`tools/characters/CharacterGallery.tscn/.gd` 提供五人模型预览和旋转。建筑器以覆盖层打开预览，关闭时释放覆盖层并保留建筑编辑数据。模型预览不创建游戏会话或计算动机。

## 构建与宿主入口

项目采用 Godot .NET 4.7.2 与 .NET 8，VSCode 默认构建使用正常 MSBuild 增量检查、并行构建和共享编译。Core 产物位于 `.runtime/build/`，Godot 托管产物由 SDK 管理于 `.godot/mono/`。

`mcp/game` 保留 environment、auto 与 input 协议。CLI 自动运行包含构建与内容验证，保持连接到结束或配置的墙钟截止时间。每个运行持有独立程序集输出，源码和输出哈希均符合才复用已验证构建；游戏状态不缓存，始终开启新局。Godot 游戏会话的接线范围与当前验收状态见 `33 实施与验收.md`。

### 推理层、主观词义与回应模式（生活会话）

详见 `34 推理与主观语义审计.md`。`RuntimeLifeReasoning` 只用人物本人认知推导“取餐—进食”“取书—就座阅读”等资源链：禁止没有可行下游用途的备料动作，奖励已就绪计划的首步，并在计划只缺一个未知量时奖励查看动作。`RuntimeLifeLexicon` 让同一个词（借/分一点、小声点、待会儿）在每个人脑中对应 DV 声明的不同义项；世界只记录行为，各人只保存自己的理解，义项分歧只有在期待落空时才以单方面申诉的形式显现。
