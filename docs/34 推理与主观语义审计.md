# 推理与主观语义审计（生活会话）

本文记录对仓库现状的代码审计结论，以及本轮在 `core/runtime` 与 `assets/data/life_simulation/rules.dv` 的改动。结论来自阅读代码并配合一次无界面 CLI 五日运行（seed 7、13），不是新的完整验收。

## 一、审计结论（改动前）

| 要求 | 现状 | 判断 |
| --- | --- | --- |
| 推理：为完成任务推出步骤，避免重复无用功，鼓励收集信息 | `GoalPlanning`/`GoalPlanningAdapter`（有界最佳优先/束搜索）与 `ActionFailureMemory` 只对战役人物生效。`LifeScenario` 给生活人物写的是 `policy.goals=[]`，没有 `goal_planning`，行动评分是单步的需要贡献加 `chain_gain` 启发。 | **生活会话没有多步推理。** 基线 2 日样本里“取书”40 次、“归还书籍”36 次，而“就座阅读”只有 12 次：大量备料动作没有下游用途。`inspect_pantry` 虽有复查间隔，但没有“因为计划缺一个未知量而去查看”的动机。 |
| 事实认知：同一事实在不同人脑中不同 | 做到了“事实层”：`ActorClient` 保存各人的 `Recall`、证据来源与冲突；`LifeObserve`/`LifeFragment` 只投影感知到的部分；`CaseTheory` 做带否定的 Horn 推理；`PerceptionBindings` 把物理身份映射成每个人自己的局部名。 | 事实与感知已分离。 |
| 事实认知：**同一个词**在不同人脑中对应不同事实 | 没有词汇层。对话类别（借口粮、抱怨噪音、延后）对所有人含义相同，`owe`、静默时长、延后时长都是全局常量。 | **缺失。** 叙事诡计所需的“词一致、义项不一致”没有载体。 |
| 回应模式 | 八种（accept/comply/conditional/defer/decline/refuse/ignore/confront），评分只看关系数值与请求代价。基线分布里 conditional 与 refuse 与邻近模式高度重叠。 | 与“六种”要求不符；请求性质与关系阶段影响偏弱。 |
| 关系数值膨胀 | 已有日增减额度、饱和、同类习惯化、衰减、阶段滞回。但 `habit` 每天清零，同一类互动每天都能重新拿满额度。 | 总体受控，习惯化可被日界清零绕过。 |
| 物品交互与需要 | 已有 9 项生理/心理需要加 3 项角色驱动需要；家具有占用、灯光、取书、取餐、库存守恒。没有厕所类物件（候选建筑里也没有），因此未加入排泄需要。 | 满足；缺口已在此说明。 |

## 二、本轮改动

### 1. 生活推理层 `RuntimeLifeReasoning.cs`
- `LifePlans(actor)`：只读人物本人的 `Recall` 推导计划，状态为 `ready`、`needs_info`、`needs_social`、`blocked`。
  - 饥饿：持粮→直接进食；已知有存粮→取餐、进食；库存未知或已过复查时间→先查看；柜子皆空但推理证明某人可请求→请求分享；否则 `blocked`，不再空跑。
  - 求知：持书且有可用亮灯空位→就座阅读；有书架且有可用空位→取书、就座；否则 `blocked`。
- 不做无用功：`LifeEligible` 调用 `LifeUselessReason`。没有可行阅读位或求知已满足时不取书；书尚未读且阅读计划仍可行时不归还（夜间例外）。
- 鼓励收集信息：计划为 `needs_info` 时，查看未知柜子获得 `info_bonus`；已就绪计划的首步获得 `plan_bonus`。数值在 DV `reasoning` 中。
- 并发减负：评分加入按人物与物件的确定性微扰（FNV 哈希，可存档复现）和轻微距离项，避免所有人在等分时选同一把椅子。
- `DecisionScheduler` 新增可选 `planningBias` 回调；`LifeAudit().reasoning` 暴露每个人的计划，供作者检查。

### 2. 主观词义 `RuntimeLifeLexicon.cs`
- DV `lexicon.terms` 声明三个词：`give_back`（借/分一点：归还义务 1 或 0）、`quiet`（小声点：30 或 240 分钟）、`later`（待会儿：15 或 150 分钟）。`lexicon.agents` 给每个人声明自己的义项。
- 一次对话中，每个参与者依据自己的义项行动并保存自己的理解（以 `<actor>.lexeme.<term>` 通信证据进入本人认知）。世界只写实际结果。
  - 借/分：受方 `owe` 只在受方理解为“借”时增加；施方只在自己理解为“借”时登记“应当归还”的期待。
  - 小声点：被投诉者按自己的义项设置静默时长，投诉者按自己的义项形成期待。
  - 待会儿：承诺到期按答复者义项，请求者按自己的义项形成期待；只有请求者期待更早时才形成一个必然落空的期待。
- 期待落空由 `AdvanceLifeExpectations` 结算：只有落空的一方得到 `last_grievance` 证据、关系变化与平静下降，另一方不知情。义项一致的交流不会产生申诉。债务得到偿还时双方各获得一次小幅互惠增益。
- `LifeAudit().lexicon` 给出每人义项、近 40 次发话（含是否一致）与全部期待，仅供作者检查。

### 3. 六种回应模式
- 模式：`accept`、`comply`、`defer`、`decline`、`ignore`、`confront`。原 `conditional` 并入 `defer`（延后承诺，到期且平静度足够时才可履行），`refuse` 并入 `decline`。
- 请求性质：每个类别声明 `nature`（question/favor/demand/offer/amends/bonding），`response.nature_bias` 给各模式加偏置，例如命令式请求更容易引起勉强答应或对抗，主动提供更难被无视。
- 态度：除原有好感、信任、紧张、债务外，`response.stage_bias` 按本人认知中的关系阶段修正，亲近更易接受，敌视更易冷处理或对抗。

### 4. 关系膨胀控制
- `habit` 不再每日清零，按 `habit_carry=0.5` 逐日衰减，使同类互动的边际收益跨日延续。
- 其余额度、饱和、衰减、滞回保持不变；申诉与互惠都经过同一 `LifeRelation` 管道，因此受同样的日额度约束。

## 三、已知限制
- 推理层是针对“取餐链”“阅读链”的有界规划，不是对所有行动的通用规划器；通用 `GoalPlanning` 仍未接入生活会话。
- 单件家具（钢琴、画架）的占用冲突依旧是 `standing_resource_busy` 的主要来源，本轮没有为此增加听觉/视觉推断。
- 词汇只覆盖三个词和各两种义项；新增词汇只需改 DV，但词义对规则的影响点仍在 C# 中（`LifeMeaning`）。
- 没有运行 Godot 宿主；只通过 Core CLI 做了五日冒烟运行。
