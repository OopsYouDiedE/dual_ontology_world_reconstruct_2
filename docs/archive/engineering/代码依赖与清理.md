# 代码依赖与清理

日期：2026-11-16  
基线：`608c3cf`
范围：`mcp/game/` 的正式运行入口与静态依赖；保留其他代理正在修改的场景、评审导出与光照模块。

## 依赖关系

正式入口链如下：

```text
run_auto.py / input_client.py / run_environment.py
                    |
                    v
                 server.py
          +---------+---------+
          |         |         |
          v         v         v
    automation.py runtime.py environment.py
          |         |
          |         +--> review_watcher.py --> review_refresh.py
          |         +--> build_runtime.py
          |                    |
          +--------------------+
                               v
                    host_process.py / build_cache.py
                    asset_bundle.py / linux_display.py
```

- `server.py` 是三类 MCP 表面的唯一协议入口：正式输入、自动运行、环境准备。
- `runtime.py` 负责正式标题入口、会话、请求和关闭生命周期；Godot 会话从项目配置的主场景启动。
- `build_runtime.py` 集中构建锁、截止时间、CLI 独立输出、Godot 本地 SDK 还原源和资源导入准备。`runtime.py` 保留 `build`、`remaining`、`DeadlineReached` 兼容导出，既有自动运行调用无需迁移。
- `host_process.py` 集中处理子进程环境、启动和进程树回收，供 `runtime.py` 与 `play.py` 共用。
- `review_watcher.py` 是评审刷新服务的窄适配层，隔离 `tools/testing` 路径注入和延迟导入。
- `automation.py` 复用 `runtime.py`，维护自动运行的截止时间、观测与持久化报告。
- `environment.py` 提供固定版本工具解析与准备；`run_environment.py` 仅负责调用该 MCP 并保存回执。
- `build_cache.py`、`asset_bundle.py`、`linux_display.py` 分别处理编译产物复用、版本化资源恢复、Linux 私有图形显示。
- `runtime.py` 通过 `review_watcher.py` 调用 `tools/testing/review_refresh.py`。该文件正由其他代理修改，本轮保持接口原状。

## 实际变更

1. 正式输入 MCP 只保留生产会话。Godot 从正式标题启动，再经“新游戏”和真实输入进入主线。
2. 移除 MCP 协议中的任意场景入口、Mock 配置、辅助测试套件和运行时内容热替换字段。
3. 移除 `runtime.start()` 中辅助场景路径解析、fixture 参数拼装及对应命令行注入。
4. `runtime.start()` 增加生产模式白名单与退役参数边界。旧调用若继续传入 `scene`、`test_config` 或 `test_suite`，会在启动构建与进程前得到明确错误。
5. `run_auto.py` 移除外部内容路径选项，使自动入口使用仓库内正式内容源。
6. 抽出 `host_process.py`，统一 `runtime.py` 与 `play.py` 的进程启动、可复现环境和所属进程树关闭逻辑。
7. 抽出 `review_watcher.py`，让运行时核心不再直接修改 `sys.path` 或导入评审刷新实现。
8. 清除自动运行内部仍可透传 `content_path` 的残留；`runtime.start()` 也会拒绝直接传入内容覆盖。CLI 与 Godot 分别固定使用仓库内 `campaign.dv` 和 `life_simulation.dv`。
9. 清除运行时对 `load`、`reload_content` 的残留接受分支及 fixture 遗留注释。
10. 抽出 `build_runtime.py`，将构建互斥、缓存复用、CLI 角色动作校验、构建回执和 Godot 资源导入从会话协议中移出；`play.py` 直接依赖该构建模块。
11. 删除 `runtime.py` 中已经迁出的构建锁、XML 还原源生成和资源准备重复实现及其无用导入，运行时文件只保留会话生命周期与协议处理。

这些调整删除了两条平行生命周期：辅助场景直启和 Mock fixture 注入。构建、会话、观测、录制、关闭与正式主线共用一条路径，错误在进程启动前收束。

## 保留内容

- `tools/test/`、`tools/testing/` 中的历史回归源码仍在仓库中，便于追溯既有覆盖；正式 MCP 不再暴露这些入口。
- 原始采集、评分轨迹、图像、缓存、`outputs/`、字幕与现有用户改动均未清理。
- `DualWorldMain.gd`、评审导出脚本、房间证物、开场、昼夜与窗光模块均未改动。

## 静态验证

- `python -m compileall -q mcp/game`：通过。
- 模块导入与依赖指向检查：`runtime.build`、`runtime.remaining`、`runtime.DeadlineReached` 来自 `build_runtime.py`；`runtime.spawn` / `runtime.terminate` 来自 `host_process.py`，正式 Godot 内容路径固定指向仓库内 `life_simulation.dv`。
- MCP schema 静态检查：正式输入参数中不存在 `scene`、`test_config`、`test_suite`、`content_path`；操作枚举中不存在 `load`、`reload_content`。
- 运行时边界检查：辅助会话参数会在构建和启动进程前拒绝。
- 退役路径扫描：`mcp/game` 中不存在 `fixture_options`、`reload_content`、`allow_external=True`，自动运行模块不再读写 `content_path`。
- `git diff --check -- mcp/game docs/代码依赖与清理.md`：通过。

依照当前测试约束，本轮没有启动辅助场景、Mock、headless 探针或 Godot 运行验证。正式标题到新游戏的运行验证由独立 Terra 沿真实主线执行。

## 剩余风险与后续建议

- `runtime.py` 目前集中管理 socket 协议、会话注册和正式启动参数。继续拆分时可将 CLI/Godot 启动命令构造收束为窄模块，并配合正式主线运行验证。
- 每次正式会话仍会启动评审监视器。依赖现已集中在 `review_watcher.py`，后续可在 server 层明确配置该钩子，或改为独立评审进程。
- `DualWorldMain.gd` 中路径避让与角色站位正由 Terra 修改。本轮没有触碰；整合后应确认输入 MCP 的 `start`、`input_action`、`click` 与实际标题/新游戏流程仍一致。
- 旧的辅助测试源码可能继续被人工脚本直接调用。若团队决定永久退役，可在单独变更中逐项标注替代覆盖，再删除已确认无调用者的文件。
