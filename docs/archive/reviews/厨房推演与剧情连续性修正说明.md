# 开局至四区首题：行为推演与场景连续性修正

## 本次范围

本补丁把 B-P 乙区小厨房首题改为场景内动作复演，并把真实流程验收到第一天四区首题与中翼对账。沿用现有开场、走廊、场景转移、`DualEngine` 数据/存档流程，不重建一套平行剧情，也未改写首日案件数据。

核验顺序为 `ded_drag → c_door`、`ded_cloth → c_wetcloth`、`ded_cuffs → c_handcuff`、`ded_window → c_window`，随后接入 `d1_meeting`。后三个推演和四场争辩继续使用原案卷题面、证物门槛和争辩界面；只有首题采用动作排序交互。

首题仍使用既有 `ded_drag` 与证物 `e_b_sleeve`、`e_b_drag`、`e_b_water`、`e_b_ratchet`。其中四段动作是一个先后推演，不是新增四个彼此独立的案件，也没有把旧设定中的时间或动机改写成新事实。

## 玩家流程

1. 从 R05 起床开场，经走廊对话后，由玩家主动进入 B-P；继续使用房间内原有的鼠标走近、E 查看与 WASD 操作。
2. 四件首题证物齐全后，`ded_drag` 不再出现一页脱离空间的纯文字选项，而是在**当前厨房场景**里进入「脑内复演」。
3. 半透明记忆角色依次演出四种动作片段：苏泠朝外扳门、侦探朝内拉回、沈鼎把湿布塞进门缝、霍铎反扣棘轮。每段显示对应角色的移动与动作姿态；片段顺序与正确时间顺序打散，避免旁白直接报答案。
4. 玩家用简洁的上下箭头排列四段动作，再确认。顺序错误时留在原场景，可重看、调整，不会写入错误结论或让流程卡死；正确时调用原 `DualEngine.solve_deduction("ded_drag", "in", evidence)`，再进入原有 `c_door` 三人争辩。
5. 争辩仍由原剧情数据决定：是否复述传声管原句、人物关系结算、后续时序均未被复演模块代替。

## 叙事与双重认知

- 苏泠的动作向门外，侦探的动作向屋内；双方身体朝向相反，呈现「开门／拉回」对同一动作的相反理解。
- 沈鼎在门槛处做的是堵缝，霍铎在门锁处做的是反扣；同为「处理门」的动作不代表同一动机。
- 复演人物是脑内记忆的可视化回声，不搬动实际 NPC、不改变他们的居室或存档位置；退出复演后清除回声。
- 仍把原因与顺序分开：动作排序能成立，不等于凭此证明谁蓄意锁人。后续 `c_door` 争辩仍要单独处理「救」的方向与传声管误听。

## 操作与 UI

- 厨房证物仍是可点击/靠近的发光标记；靠近时使用底部 E 提示，3D 名牌只在鼠标悬停时出现，减少角色名、证物名重叠。
- 底部现有操作提示增加现场线索计数，仍只有一条轻量提示，不新增常驻侧栏。
- 复演面板使用半透明遮罩并保留房间画面；四条短动作、上下调整、重看与确认是唯一操作控件。
- 四件证物未齐时不接管题目，继续沿用原推演弹窗的缺证提示与取证暂停机制。

## 代码边界与连续性

- 新增 `scenes/dual_world/KitchenOrderReplay.gd`，把角色回声、动作播放与时间线控件隔离在厨房专题模块内。
- `DualWorldMain.gd` 只增加一个 `ded_drag` 委派点；`KitchenExploration.gd` 只负责启动专题模块、收敛证物提示与结束清理。
- 证物判读、最少证物数、推演结果、案件抽屉重试、自动存档仍由现有引擎处理；没有把推理规则复制到 UI。
- 场景不切去新画布，不把过场叙述硬塞进全局故事队列；复演结束即回到当前房间与原始剧情节拍。
- 原流程离开 B-P 时厨房漫游接管层可能继续存活，导致厨房专属标记/UI 与后续 A-P、C-P 剧情房间脱节。现在主场景检测到离开 B-P 时先调用厨房模块 `end()` 清理并归还常规 UI，再开始既有门廊转场；不替换或跳过角色进场动画。
- 首日四区门禁的开放条件仍由原剧情时间与勤务通道事件控制（A-C 三门随 service map，第四区按原时序），不是本补丁新增“答对四题即开门”的规则。集成验收确认四题完成后按原时序进入四区对账、门禁状态正确；若设计目标是让答案本身成为门锁条件，需要另改场景设定与门锁规则，当前没有偷偷改写这一因果。

## 验收

开发环境实际下载并运行 Godot **4.7.2-stable 标准版**。使用 Xvfb + Mesa llvmpipe 的实际图形渲染运行厨房测试，检查：

- `tools/test/kitchen_order_replay.gd`：B-P 真实房间加载、厨房接管、四件证物触发复演、四个记忆角色生成、顺序错误不结算、可调整为正确顺序、结论写回原引擎并自然进入原 `c_door` 争辩。
- `tools/test/kitchen_flow.gd`：厨房的鼠标/靠近交互、镜头方向移动、对话期间移动、贴边滑行及 Esc UI 切换。
- `tools/test/first_four_questions_flow.gd`：从真实开场、走廊主动选门进入厨房，经自动搜证与测试驱动的正确选项，走完四项首日推演和四场原争辩；检查厨房模块在离开 B-P 时结束、房间网格同步当前房间、抵达 `d1_meeting`，以及原有四区门禁最终开放。

实际图形渲染在 Xvfb + Mesa llvmpipe 上通过；复演截图为 `.runtime/screens/order/replay.png`，首日流程各题/争辩截图为 `.runtime/screens/first_four/`（均为本机测试产物，不进入补丁）。无系统音频设备时 Godot 回退到 dummy 音频；不影响画面和交互检查。
