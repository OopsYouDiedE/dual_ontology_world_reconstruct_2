# 建筑房间拓扑

同层墙网决定房间。墙记录中线、厚度、高度、节点和洞口；房间记录有界闭环、节点及相邻墙。共享墙同时属于两侧房间，两侧各使用该墙朝向房间的一面。

墙端点、T 接头及交点是房间轮廓节点。端点落在其他墙段内部时，房间图自动切分该墙段。编辑该接头时，宿主墙实际插入节点，并更新洞口所在墙段及沿墙距离。节点的批量移动使用修改前的统一快照，避免相邻节点连续移动时互相覆盖。

房间地板由中线闭环按逐边半墙厚向内偏移得到，转角使用相邻偏移边的交点。绘制铺装时进一步裁剪到地板轮廓。门窗属于墙，开洞不破坏房间闭环。

移动墙、节点、修改墙厚或删除墙后，重新计算同层房间。断开闭环即失去对应房间地板；删除中间隔墙使两侧空间合并。房间轮廓节点与墙网共用，不能把派生地板顶点单独移离墙面。拖动整个房间时，其轮廓关联的墙节点一起移动，并同步相邻房间。

没有闭环的剖面图可以保留手绘地板。首次形成闭合墙网后，该层地板由房间派生，不再使用独立地板轮廓作为房间边界。由独立地板建墙时，中线外移半墙厚，使墙内面贴合原地板边界。已有派生房间不重复向外生成墙环。

层、墙、洞口和派生房间数据共同进入 JSON／YAML 与撤销快照。Godot 候选导出使用当前派生几何。

房间预设保存完整闭合外围墙，默认显示全部墙段。F01 的中间平台与上层回廊作为独立楼面保留，不对这些楼面另行封闭围墙。

“显示／隐藏”窗口按类别、单段墙和单个地面、楼梯、栏杆、家具控制 3D 可见性。墙段的门窗随该段显示；相邻两段均隐藏时，共用装饰柱也隐藏。此状态独立于建筑数据，不改变二维蓝图、房间拓扑或撤销快照。实体与线框遵循相同可见性；JSON、YAML 和 Godot 候选均输出完整结构。“全部显示”恢复所有构件；载入预设时也恢复全显。

### 第一版试作

1. 输入房间功能、面积范围、必须相邻或直连的空间、入口与确定性种子。先在单层上排房和走廊，再把候选转换成建筑器现有的墙、门窗和楼层记录。
2. 在隔离的候选状态里派生闭环和楼面，分别检查房间邻接、门洞连接和实际可行走路线。家具放入后再检验一次通行。预览通过后，整组作为一次撤销操作提交；保留预设、证物布局与既有 ID。
3. 先用一层带走廊的测试平面验收：断墙取消闭环、移除隔墙合并房间、开门改变连通但保留闭环、家具避开门区，取消候选保持正式状态。多层再用 `F01` 的分叉梯和回廊检查楼梯落点与跨层动线。

FreeSO 在此仅用作机制参考；实现使用本仓库代码和资产。

### B-P：布局与角色效用实测

角色决策参考 FreeSO 的 [`VMFindBestAction`](https://github.com/riperiperi/FreeSO/blob/4c6b3e8f5835b228723caea3c9f683c62f244f73/TSOClient/tso.simantics/Primitives/VMFindBestAction.cs#L148-L305)：先检查交互条件，再评估需求改善和距离。Godot 生活模拟用实际可走的物件接近路线替换原有的直线距离估计，沿用 DV 的每米成本。路线为空时排除该动作；执行时复用相同的寻路规则。CLI 保留逻辑距离模型。此项覆盖物件交互；角色间社交、主线演出和正式厨房数据保持原样。

构建后用 Godot 4.7.2 .NET 运行 `godot --headless --path . --script res://tools/test/kitchen_layout_utility.gd`。脚本复制正式 `B-P` 建筑预设、保留家具和物件 ID，只在副本中插入隔墙。固定侦探位置和种子 `47`。三个有隔墙的版本派生出相同的两个房间；丢弃候选后，原数据和撤销历史保持原样。

脚本逐段检查两条可走路线，并向物理宿主报告进度和到达，确认已选交互能开始。这是墙网、寻路与决策的无画面回归；原房间的实机入场与鞋跟印近景另见定点测试 `2762a37a8d70cf12`。

建筑编辑器现已提供 **Generate Layout**：输入种子和 1–4 对房间，生成带走廊的单层草案。墙、地板、门窗、栏杆、新放置的家具与楼梯、自动布置及清空房间均通过隔离草案预览，提交记作一次撤销。生成方案要求预期闭环数量正确、每个房间有站立空间、全层室内连通；手工编辑允许作者有意隔断房间。逐墙段计算门洞通行，以免门洞清掉相交墙、家具或凭空产生承载面。楼梯阶段仅有几何预览。详见[机制迁移与验收清单](freeso-mechanism-migration.md)。
