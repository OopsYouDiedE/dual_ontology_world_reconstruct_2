C01人物建模论文P0

Team Fortress 2：先读出人物轮廓

来源所示
Valve 的论文把职业的可辨识性写进剪影、比例和着色；同一角色在不同光照下仍需有清楚的轮廓。
学院试法
给四名幸存者各定一个远距线索：外套长短、肩形、装备体块或持物姿态。先做单色剪影表，再雕面部和缝线。
怎么验
同一走廊用正面、背面和三分之四角度截帧，遮名字和专属配色，让试玩者在营地与出征两种光照下辨认。

C02人物建模开发演讲P1

Guilty Gear Xrd：按镜头调整体块与明暗

来源所示
Arc System Works 的 Junya Motomura 讲解如何用 3D 模型做出手绘动画的形状与光影；演讲包含模型、法线、动画和镜头的例子。
学院试法
把头发坯形和脸颊、鼻翼、眼窝先分清，再用定向法线与受控明暗收拾脸部。优先用在固定侧视机关和重要对话近景，自由第一人称镜头用同套模型实测。
怎么验
同一人物在三种视角和两组灯位下保有眼口轮廓，脸部阴影在旋转时无明显跳变。

C03人物建模馆藏／档案P0

约 1905 年燕尾服：按裁片读年代

学院试法
为正式外套定稿正背两张裁片草图：翻领沿前襟折转，收腰和后摆改变剪影。勘测服、工装另找同年代服装取材，保留各自的活动余量。

C04人物建模文档／标准P0

Blender → glTF → Godot：固定骨架交付合同

来源所示
Blender 文档说明 glTF 的蒙皮和动画导出；Khronos Validator 检查文件结构；Godot 文档通过骨架配置及 BoneMap 处理重定向。
学院试法
保留现有角色资产与使用方：固定 A-pose、尺度、手部挂点、骨名和动作语义；肩、肘、髋、膝留变形环线，先用一名角色验证蒙皮与导入，再批量出装。对白、持灯和手轮可复用骨架，分别验手与道具接触点。
怎么验
导出通过结构校验；导入后逐验脚底、手挂点、动画循环与手轮接触。共享动作让五名角色在三种场景入口下使用同一套挂点语义。

C05人物建模开源／素材P1

Quaternius：用 CC0 动作库对拍

来源所示

学院试法
选 idle、walk、run 做灰盒动作标尺；保留学院已有动作语义，持灯、扶栏和转轮再按场景握点微调原有动画。
怎么验
记录包版本及来源；逐段比较脚滑、根运动和转身衔接，达到项目自身的动作基准后再评估是否引入。

C06人物建模论文P1

XPBD：让衣摆在动作后有重量

来源所示
Macklin、Müller、Chentanez 用 compliance 改善 PBD 刚度随时间步与迭代次数变化的问题，给可控的柔顺约束提供参考。
学院试法
先修蒙皮、纸样松量和静态遮挡；只给衣摆和悬垂部位做低成本二级运动比较。现有 GarmentDynamics 是对照基线，此处的 XPBD 是候选方案。
怎么验
走停、转身、互动三个镜头记录恢复时间、最大穿插与每帧开销；对比不同帧率下的摆动幅度和收敛，确认质量改善后再换求解器。

S02场景建模开发演讲P0

Skyrim / Fallout 4：按建筑接缝做模块

学院试法
让证词页先收集原话和物证，再用可选择的证据引用提交质证。错误时标出待核对的断言及其来源，保留玩家已确认的词条。

04 / PRODUCTION ORDER

建议先交付一个可玩的制作样段

选择「从 Field card 读规则 → 找到热厨传菜口 → 操作实体按钮 → 回读档案」，把人物、场景、界面与规则在同一次实机走查中合起来验。西翼侧视机关用独立用例保住原有视角。

01 / 人物

先定一名侦探的交付规格

现有导入和动作挂点作基线。先修腰口、衣摆和袖口，定大轮廓与裁片，再把同一套走、坐、持灯、按按钮用例复用到四名幸存者。

验收：同尺度正、侧、背与工作姿态清楚；手指对到按钮，外套在抬臂和蹲坐时与裤面分离。先过 剪影 和 导入合同，再评估服装模拟。

02 / 场景

在 ArchBuilder 里完成一个门槛模块与一个近景机关

门槛样块实测拐角、旋转与邻接；传菜口按照导轨、门扇、按钮、卡扣分件。细节集中在玩家靠近、触摸、观察的面上。

验收：入口与交互机位固定留图；碰撞随门扇变化；跨时段外窗亮度改变，内窗和无窗区域仍由各自室内方案撑起层次。见 模块、光照。

03 / 界面

做一张 Field card 和一组仪器状态词

保留「条文／新证据／前任边注」分区和位置回跳。按键、回放进度、年代及锁定原因用短英文配合形状；长证词留在完整纸页。

验收：键盘闭环、窄窗口、静音和灰度都可辨认关键状态；关闭记录页会回到原来的目标和输入方式。见 纸面工作流、可读性。

04 / 谜题

做一套可重复走的机关测试

热厨按“观察 → 用一次 → 用规则验证”编排；西翼七步记录保留独立舞台和逐步重放；Vesper 继续用两年代状态图作逻辑回归样本。

验收：规则枚举覆盖通关、失败、复位；实机确认镜头、输入、模型、反馈一致，再查暂停继续与奖励幂等。见 七步时间线、状态层。

判断顺序：先把入口路径、剪影、物理动作和证据反馈做清楚，再扩充模型数量、纸张装饰及着色。以同种子、同机位成对截图和一次完整实机操作判定是否进入下一批制作。

05 / SOURCES & SCOPE

资料口径

研究日期：2026 年 11 月 20 日。共四类方向、每类六条；条目可包含多份来源。

  • 外部资料：优先列开发者、发行方、官方技术文档、原论文和作者仓库。原神／星铁条目标明玩家实录或攻略；它们用来核对实际镜头与输入。外站素材由各原出处提供，报告内联画面来自学院。
  • 项目基线：主入口与测试、夜行学院重构、Vesper 调查与规则测试、热厨灰模与叠绘。建筑继续由 ArchBuilder 提供，房间连接沿用种子约束塌缩；营地自研决策及队长指挥保持现行分工。游戏面向玩家的验收文字使用英文。

  • 范围：P0 是先验证，P1 是已有基准后再试。报告记录资料和制作建议；每项的项目状态以实机说明为准。
