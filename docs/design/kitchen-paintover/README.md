# 热厨：入口视线的绘制任务

`kitchen-blockout.png` 是新设计的三空间白模，不是游戏实机或目标图。`blockout.py` 在 Blender 4.2 中可重建。原 kitchen.xml 的单间另有实机留证。生图采用 **edit**，输入本 PNG；先获得同机位的目标图，再改游戏。

## 给绘图工具

在输入图上绘制一间仍能运作的老学院热厨，保持相机、主要轮廓、门窗开口、长案和右侧通道的投影位置。左侧是被熏黑的铸铁炉、挂锅和宽排烟罩，橙色余烬照出长案侧边带磨损的木纹。案上留一册翻开的油渍笔记。正面中央是传菜窗，露出垂直导轨、拉手与半收起的旧金属窗板。窗后走廊窄而暗，右侧通道尽头冷库门虚掩，冷青光落在湿地砖上。这个亮点应当引导人先看门缝，而不是照亮整个厨房。远处瓷砖纹样多重复一段，制造轻微的空间错觉。保留人物能通过的通道。低多边形、成组色块、可读剪影；以缩到 384×216 仍看清炉口、窗板、门缝为准。无文字、UI、轮廓高亮或场景说明箭头。

## 拿到目标图之后

1. 将三空间回写到原生 FreeSO 蓝图；保留原 Godot 角色模型、动作、第三人称操作。用目标图固定玩家入门视线、道具比例、主色及明暗。只调这一个节点。
2. 传菜窗拉手驱动窗板沿轨道落下，终点发出碰撞声并挡住观察线；冷库门绕铰链转动，光缝随开度变宽；炉门开合露出余烬。玩家和队员交互走同一个动作和状态，不走 HUD 直接改结算。灯色与门状态来自模拟，渲染呈现它们；给色觉差异提供光脉冲节奏等第二条线索。
3. 第一条自动规则：守望者听到斩击声停止 → 拉窗。明确谁站在能听见的位置、谁获知了规则。比较手动下令、正确内化和错误内化三次现场后果；分别记录下令与执行耗时。先用时间、照明、信息暴露支撑取舍。
4. 验收保留同机位的白模、目标图、实际 Forward+ 图及操作前后帧。隐藏 UI 请观察者指认灶台、可操作窗、危险所在和可走路线；再用现有第三人称视角走一遍。核对门窗开合中途的碰撞和视线，检验光色变化能否在最低显示分辨率下辨认。
