# 角色行为涌现：无画面对照批测

`--compare-emergence` 使用生产 CLI 的 DV 角色会话。它让侦探也交给引擎决策，用与普通 CLI 相同的核心步进、观察、资源占用、行动成本和结算。它的时间参数是剧内累计分钟；`1440` 表示第一天结束，`7200` 表示五日窗口。实验只在内存的新局快照里改一个人的一项初始需求，不写游戏存档或 DV 声明。Godot 五日故事演出的节拍由另一套引擎处理；此报告描述 DV 模拟里的角色行为。

从项目根目录执行（使用项目环境的 .NET 8）：

```powershell
dotnet build core/cli/DuelView.Cli.csproj -c Release
dotnet .runtime/build/bin/DuelView.Cli/Release/net8.0/DuelView.Cli.dll --compare-emergence artifacts/review/emergence-day1.json 1440 32
```

参数依次为报告路径、剧内截止分钟、候选数和可选的 DV 场景路径。默认用 `campaign.dv`；前 32 个候选覆盖十六人各自的初始体力单独下调和上调 25 点（范围 0–100）。可把候选数扩到 96，按同一规则继续检查社交需求和口渴。代管者保持基准设定，所有局使用相同种子。基准独立跑两次；候选最多并行四局；最高分再单独重跑。

**每个有来源的同伴响应记 1 分。** 对未被修改的角色，找两局第一次做出不同且均已完成的行动。如果该角色在决策时已掌握一项行动条件中的事实、事实可按行动序号或世界修订号追溯到另一人的已完成行动，而且基准到这个决策点还没有这次上游行动，给 1 分。每位同伴最多贡献 1 分。报告另外记录只观察到行动分歧、但未能核对来源的同伴人数。只改变行动时间、只少跑了几个动作、同一人重复工作，均不计分。

候选须保留基准已有的集结与用餐行动，达到同等观测窗口（或完成战役），且无引擎记录的规则越界和意外失败；若基准已完成战役，候选也须完成。按响应人数排序；同分按扰动角色、需求、增量的固定顺序选出一个供复盘。没有任何合格响应时，报告的 `best` 为空。复跑不同则返回非零，报告保留两项复现状态中的结果。

报告包括 DV 内容哈希、时间、每局进度、动作序列，以及获分响应的两条行动、已知事实、上游行动和证据 ID。计分给出的是**可回看的因果线索**：它会漏掉只通过疲劳、占位或情绪间接传递的行为，也无法凭单个得分判断角色写得好不好。复盘宜优先检查两件事：差异有没有角色动机，上游差异有没有改变实际协作。

## 首批实测：第一天，32 种体力开局

2026-11-18 运行至剧内第 1440 分钟。DV 内容哈希 `e7098ac24fbdec89a9ea15f8f3f1c5afb8fd515b50ea321223ee3f4188b8c2f2`。两次基准、32 种单人扰动和一次冠军复跑共 35 局，用时约 230 秒。基准与冠军均精确复现。32 局通过筛选，26 局有可追溯响应；最高 7 分，第二名是沈鼎体力下调 25 点（6 分）。

**推荐复盘：苏泠初始体力从 69 调到 94。** 基准里她在约 09:12 先歇一歇，这一局她在这个节点之后的下一项行动是约 09:43 去汇合。14 位同伴随后出现首次行动分歧，7 位达到来源核查条件。此局完成 614 项行动，基准完成 623 项；两局均保留相同的 13 项已完成集结行动和 16 项用餐行动。

这三处都是可以从行动回查到证据的局部变化。报告没有逐步证明从苏泠的体力变化到七位同伴响应的完整传导链，也没有测游戏画面。推荐先以这局作复盘样本，再决定哪个交接机制值得带入 Godot 正篇。
