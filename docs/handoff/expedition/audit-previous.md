## 原稿第 1–3 页｜入口、关卡、资产
### P1｜三种入口，三种结果
总览提了 Run 和 L03，却没有把十房规则课与十机制展台逐关分开，也没交代两者与战役的终局。Run 从领册走到晨钟；Evaluation 的 R1–R10 用独立裁判抵达 Main Camp Hall；Lab 的 L01–L10 用来操纵装置。复用关号时必须带系列名。刚才的镜像找不同、隔断试重、横桥分批渡河分别落在本地 R2、R5、R7；独立 L03 检验的是另一件事：两人在看不全的空间里如何交接视线。
### P2｜从“看见”到“签署”少了关键选择
原句“他会修正”把举证、提议、接受写成一次自动更新。Rules.gd 同时维护三种解释：任何凝视危险、共同凝视危险、危险与凝视无关。单人冷白连续 84 步即可取得有限反例；若先连续观察到 5 步双视红光，随后单人冷白门槛为 27 步。Airlock.gd 还要求面对面提案；三项里只有改 H-03 为“同伴可见地转开时才看”会获准。玩家可只靠白光签有限例外，证据不足以签双看。初次零眼不凭空生成桥；60 步宽限从已承重后撤眼开始，第 41 步持续叠看致死。
### P2｜图 2、3 证明了哪些视觉信息
入口与红警截自不同状态，一对静帧无法判断交接节奏或玩家是否看见踏边。读既有 final-witness/optics/survey.json 的 07–09 同眼位反例及 forward/{blocked,early,late,clear-repeat}；核头向、靴位、同面光肋和遮挡。真人第一次能否发现远岸足标、理解敲击仍待测。本次入口重拍可见 Hale 背影偏暗、左墙牌在起点斜视时很小；这是本机开场观察，不能据此裁定整关可读性。
### P3｜“三条路”混用了生产来源和运行时表示
现有组件库已定义 A 参数化、B 文字生成普通道具、C 概念图后生成特色件；门框可走 A、活动扇走 C。Blender 是整理与交付环节，Godot 运行时负责装配、碰撞与状态。保留三种来料，通过现有 catalog 的 ID、mount、production_route 收口。RogueRoomView.set_blueprint_room 对 kitchen.xml 特判转 Kitchen.read_plan，其他房间走 Blueprint.read；共用装配入口已经存在，跨所有资产的统一格式及自动验收仍是提案。
## 原稿第 4–5、7 页｜画面和人物
### P4／P7｜后处理的证据只能支持四种已拍组合
capture-evidence.json 中四张大厅对照全部关闭 Glow。live_evidence.py 记录大厅启动恰好是 Glow 开、GI 关；图 5D 才是关 Glow、开 GI。把生产建议与这两组开关分列。图 5 没有单独的 Glow、TAA、替代后端或移动镜头对照；不能据此给这些方案作性能排名。HallLook 还固定了 SSAO、对比度 1.10 与饱和度 0.95，复拍时应保留这些控制变量。
### P4／P7｜墨线在动镜头里如何停调
HallInk 读取深度、法线和 HDR 屏幕亮度；4.5–19 m 改采样偏移，22–37 m 淡退，高亮区主动减线。shader 没有时间驱动的抖线。迁移时锁机位、材质、分辨率及曝光，再依次单切表面色阶、角色反壳、屏幕线和 GI。补走动、转头、远近切换序列；墨线若让地缝被认成断桥、眼脚标丢失或闪烁，先撤屏幕线，再调局部几何。记录等长稳定窗口的 p50／p95 帧时；预算由目标设备另定。
### P7｜窗光的实现写错；数值本身大体正确
原稿称“窗外方向光”。RoomLighting.gd 用相邻两侧地板占用筛外窗，在内侧放 OmniLight3D，随小时改变颜色和能量；灯与炉火受房间氛围控制。实载 RogueRoomView.tscn 读回 Filmic=2、4 级 SDFGI、MSAA 枚举 1（2×）；Airlock 用 4×。大厅的 0.67 是 GI 能量，0.28 是反馈，均属大厅样板。调大厅参数不会自动更新战役和 L03。
### P5／P7｜把三个人体、两种服装测试分开
177 cm／6.5 头身是角色设计目标；有精确地标实测的是外部底模试装，不能把数值贴到穿靴的 R-05 正装。战役仍由 Roster.attach 映射 17 个编号模型；独立关把 r05_formal.glb 用于 Hale。试衣图与 L03 校验过同一网格哈希，人物身份、灯、姿态、运行材质仍可不同。批准正装用作关卡光学／动作基线；给侦探定身份时仍以原 model_06 服装设定和设计地标验收。
### P5｜动作接口的选择缺少迁移门禁
AcademyCast 的五个 glTF 与 R-05 各有骨架和动作来源。前者四个角色及装配脚本仅在本地；GarmentDynamics 是两圈骨点与胶囊约束，112 次回调通过只覆盖该夹具。先交骨名映射、休止姿态、根朝向、手部挂点与衣件依赖；同机位对照蹲、跨、转头和接桥时的肩、膝、鞋袜、脚标。以 R-05 的光学复验作退出条件。角色两处柔阈值和反壳保留独立尺度，勿直接复制大厅三段参数。
## 原稿第 6、8–12 页｜发布与取证
### P6｜成功列表漏报失败；两个验证对象被混称为战役
夜班 11 遭遇和 L03 专项是绿的；独立十房评测是红的。三者分别用 FirstWatch、Airlock、Evaluation 标题报告。306/306 是 B 段规定角度的光学采样，不是 306 次首玩。本次重跑同样通过。已知路线的 clear、全知见证、公开输入回放、黑盒选手、真人初见各回答不同问题，不能合算通过率。统一协议只获选，尚无一次总运行证明所有层都通过。
### P6｜证据指纹只覆盖一个配置文件
GameControl.gd:90 的 project_sha256 是 project.godot 的 SHA-256；换模型或改裁判可以保持该值不变。归档至少加 Git 提交、工作树补丁／未跟踪依赖摘要、引擎、种子、场景、机位、实际视口、帧与有序动作。盲测先冻结政策和裁判，再抽留出种子；已知安全解用于可达性，不能用同一批种子验证独立泛化。
### P8｜路径存在与玩家能启动是两件事
project.godot → Run.tscn → FirstWatch.gd 已核对；SCENES 注册 13 个别名。Boot.tscn 仍引用已删除的 Boot.gd，不能当作可运行备选；Run.gd 是留存脚本。architecture_lab 是 rogue 的参数，非第二个正式入口。Lab 默认第三展位转独立 L03，用 --lab-archive-observer 才进旧反相展位。调试快捷键／审片模式须在证据里标出。
### P9–10｜64 个字面路径都存在，其中 14 个只能在本机找到
逐项检查了生成稿手列的 64 个文件或目录，并用 git ls-files 检查是否有跟踪内容。14 项没有跟踪内容，包括 CastFitting、Folio、Visit、ShallowWater、HM08 目录与 bake、face_graft、standard_fit、两份设计说明及四处 .runtime 资料。依赖盘点的例子是本地 Hall.gd → CastFitting.gd → AcademyCast.gd → 四名新人的 glTF 与外置缓冲。附录列出路径不代表干净检出能复现。现把逐项结果与现有依赖表附入 PDF。
### P11–12｜78 个脚本是按名字筛选，不是完整可执行测试计划
生成器按目录、后缀和命名模式取样，把回放器、生产辅助函数和测试放在同一表。MCP 自己会隔离用户目录，直接跑 headless／Python 并不自动经过这个宿主。先按测试对象选命令和预期结果，再查路径。最短复验：python -m unittest discover -s core/rule_evaluation -t . -p 'test*.py'；Godot --headless --path . -s res://tools/physics_lab/verify_airlock.gd；实机 on(scene='observer_airlock')。命令从仓库根运行，Godot 用项目的 .NET 版。
