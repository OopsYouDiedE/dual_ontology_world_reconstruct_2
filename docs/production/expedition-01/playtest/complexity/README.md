# 预算驱动的地图候选生成

本工具用于首次出征下一轮白模设计。它输出带动作和前置条件的逻辑图，以及新增双门房间的箱体三维布局。交付物是生成候选和筛选工具；正式关卡继续使用现有 ArchBuilder、美术、剧情与物理。

## 操作

```powershell
$d = 'docs/production/expedition-01/playtest/complexity'
python -B "$d/plan.py" --seed 31 --map-cap 20 --decision-cap 6 --global-decision-cap 6 --out .runtime/complexity/standard.json
python -B "$d/verify_rooms.py" --seed 31 --map-cap 20 --decision-cap 6 --density 1 --max-layers 3 --out .runtime/complexity/verified-standard.json
python -B "$d/view.py" .runtime/complexity/verified-standard.json .runtime/complexity/index.html
python -B "$d/test_plan.py"
```

- **地图总量**：房间节点数 + 2 × 独立环路数；独立环路 = 去重后的空间连线数 − 节点数 + 1。两个交互通过同一座桥只算一条空间连线。走廊延长会增加空间预算，但不增加决策预算。系数 2 是设计权重。
- **路线决策量**：从零物资出发，按「节点 × 已获资源/知识」遍历；在当前状态有 `k` 个有实际区别的动作时记 `log₂(k)`，沿一条推进路径相加，取通关路径中的最大值。拿到节拍器才有投饵选项，带油才能走消耗灯油的绕路。报告列出峰值路线与产生选择的状态。
- **全图决策量**：每个节点取在可达状态下实际出现过的最大选项数，累加各节点的 `log₂(k)`，用 `--global-decision-cap` 封顶。这是对分岔密度的预算；把它与角色单次承受的峰值分开。只计算向目标推进的选择，不计原路折返、等待、读字难度或即时操作负担。
- **候选集**：固定九个进度节点；六个可选分支各自有「关闭 / 插入 / 插入并延长」三态，共 729 个组合。固定骨架保留大厅、档案、试板、总闸、源井、取芯、楼梯、检修回廊和撤离终点。模型把不与新交互相关的固定地标折叠进骨架；它不移动营地或天文台。缺前置而完全走不到的支路剔除；符合硬上限的图中，优先选两项预算利用率较高者，用种子打散接近的候选。同种子同预算可复现。
- **物理筛选**：`verify_rooms.py` 从图中提取新增的双门节点，为每个节点派生独立稳定种子，调用同目录上级的 `clutter/run.py`。所有房间都必须通过布局检查和胶囊正反向行走才签发 `accepted:true`。设计中某个房间换名会重新摆放该房间。房间原型共用同一个双门尺寸；正式拼接时仍须把门口与实际相邻房间对齐，再运行整关测试。特殊机关、楼梯和固定地标不由箱体原型覆盖。

### 实测（seed 31）

| 档位 | 房间节点 | 独立环路 | 地图用量 / 上限 | 路线决策量 / 上限 |
|---|---:|---:|---:|---:|
| short | 10 | 1 | 12 / 12 | 2.00 / 3 |
| standard | 14 | 3 | 20 / 20 | 4.00 / 6 |
| dense | 18 | 5 | 28 / 28 | 5.17 / 9 |

标准档从 153 个预算内候选中选出；新增五个双门节点，具体三维坐标、支撑件、胶囊终点和耗时见 `verified-standard.json`。同样保留地图上限 20，将路线决策上限降到 2 后，得到 13 个节点、两个独立环路、路线峰值 2 bit。预算有上限，设计者可以留下余量。

本次联测：`density=1.0, max_layers=3` 时，五个房间共 231 件，正反向 10/10 通过；同一张图改为 `density=0.55, max_layers=2` 后共 78 件，正反向仍为 10/10。密度调整仅作用于堆放，沿用相同的图和房间种子。独立的 20,000 组堆放筛选与几何/胶囊计数见 [clutter](../clutter/README.md)。
