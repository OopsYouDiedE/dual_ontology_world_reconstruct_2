# 主线快照与定点续测

正式主线中的 `StoryCheckpoints` 每秒保存一次运行快照。F6 另存一份带时间的快照；关闭窗口、MCP close 或启动器中断时保存最后状态并排空采集线程。

快照覆盖规则引擎、当前实际房间、走廊演出舞台、对白与剩余时间、侦探和同伴位置/姿态/动画时间、行走路线与交互意图、原相机、家具构件、采样进度、证物选择，以及三段推演的阶段和阶段内时间。恢复时重新绑定交互完成回调。已播放的一次性音效从下一事件继续。

## 启动与中断

在本工程根目录运行：

```powershell
.runtime/python/Scripts/python.exe tools/testing/story_checkpoint.py
```

输出会给出本次会话目录和 `latest.json`。Ctrl+C 或关闭游戏窗口会先保存后退出；也可以从另一个终端请求结束指定会话：

```powershell
.runtime/python/Scripts/python.exe tools/testing/story_checkpoint.py --stop .runtime/checkpoints/<会话目录>
```

原场景续测：

```powershell
.runtime/python/Scripts/python.exe tools/testing/story_checkpoint.py --snapshot .runtime/checkpoints/<会话目录>/latest.json
```

固定时长的无界面代码检查，可加 `--headless --duration 3`。直接使用 Godot 时，入口参数为 `-- --dv-snapshot=<工程内快照路径>`；Boot 自动进入正式主线并恢复。MCP input `on` 同样接受 `snapshot_path`。

## 保存与来源

JSON 外层记录工程标识、PID、时间、房间、演出控制器及 SHA-256；内部使用 Godot 禁止对象反序列化的 Variant 格式，保留 Vector/Transform 等原生数值类型。后台线程将完整新版本写入临时文件，保留 `.previous` 后替换当前快照。当前文件受损时会尝试完整的上一代，并在恢复回执中记录路径。

系统强制结束进程时，可恢复到最近一次已落盘状态，正常每秒一次。每个 MCP/启动器会话有独立输出目录，停止请求绑定实际 PID。快照只允许来自当前工程目录；同目录修复代码后仍可重放原快照。快照及 Mock 续测统一标记 `acceptance_eligible=false`，正式验收由独立 Terra 从标题新局采集。

## 开发验证

`tools/test/checkpoint_roundtrip.gd` 覆盖醒来、厨房、采样和走廊；`tools/test/checkpoint_edges.gd` 分别以 `--probe=transit`、`reconstruction`、`backup` 检查转场、推演与备份恢复。定点脚本运行时加 `--dv-checkpoint-auto=false`，避免自动快照干扰计时。测试用快照会保存在 `.runtime/checkpoints/fixtures/`，可直接作为续测输入。

第一章修复使用这些定点入口复现问题，房间快检通过后再提交给独立玩家盲测。
