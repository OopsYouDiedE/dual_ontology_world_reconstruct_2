# 第一章主线评分与修正

入口为 `artifacts/review/index.html`，`gameplay.html` 同步展示相同主线内容，`评分总览.md` 和 `游戏场景评分.md` 提供带图版本。页面顺序固定读取 `assets/data/test_scenarios/gameplay_review_plan.json`：起床、走廊、厨房调查、厨房推演、检修路线、跨区、暗井、黑板诗、四院、晚餐、章节收束。

每段第一个元素是实机轨迹图序列。随后依次显示段名、合格／不合格／待评、实际修改次数、七项分数及原因、本段反馈与修正、历次实机评审。单帧明确标记过程待补。开发快照图片标记“开发快反，验收待评”，保存原图及来源 sidecar，与独立验收区分。暂缺的实机画面保留待采集位置。

正式主线评分从真实标题新游戏开始，由独立 Terra 记录观察。七项依次为流畅度、字数、动作音效、响度、视听剧情替代、参考图相似度、剧情流畅性。每项 8 分合格，缺项为 null。完整完成且七项均达到 8 分，段落才显示合格。低于 8 的已评分项或实际阻塞显示不合格。当前 Git 提交匹配的评分才进入当前结论；历史版本评分保留在所属段的折叠历史中。来源隔离记录和辅助采集统一放在 `archive.html`，原材料持续保留。

修正根据本段反馈开展，每次记录观察到的问题、实际修改、复测结果与证据。已有提交的修复历史存于 `artifacts/acceptance/mainline_changes.yaml`；后续统一通过项目 MCP 追加，`kind: change` 每条计一次修改。检查和完成确认分别计为事件，修改次数保持独立。共享基础设施使用 `segment_id: project`，在页面底部实时进展展示。

## 项目 MCP

项目配置 `.codex/config.toml` 注册 `dual-ontology-review`，运行位置和服务入口均绑定本工程。所有在本项目工作的智能体遵循 `AGENTS.md`。当前会话若工具集合已经固定，可通过项目客户端使用完全相同的 stdio MCP：

```powershell
& ./.runtime/python/Scripts/python.exe mcp/review/client.py progress_append --arguments '@.runtime/review-request.json'
& ./.runtime/python/Scripts/python.exe mcp/review/client.py review_append --arguments '@.runtime/terra-review-request.json'
& ./.runtime/python/Scripts/python.exe mcp/review/client.py render
```

每次修改或检测完成，立即 `progress_append`，提供 work_id、计划内 segment_id、kind、summary、真实 result、实际 revision 和现有 evidence 文件路径数组。服务生成实际时间、PID 和证据哈希，持久化 YAML 后自动刷新 `live-progress.js`。HTML 最底部每五秒读取这份快照，每事件增加一行。旧行保持原样。

完成工作后，另行 `progress_append(kind: complete)`，引用同 work_id 的全部 change/check 事件 ID。完成确认是独立事件；后续工作使用新 work_id。具体输入与恢复规则见 `mcp/review/README.md`。

独立 Terra 使用 `review_append(work_id, summary, record)`。record 保留现有 mainline_reviews 校验格式：schema_version、唯一 id、segment_id、实际 revision、带时区 observed_at、reviewer、status、七项 scores 和 score_reasons、report、images（path、sha256、caption）、source（real_mainline、title_new_game、session_id、on_receipt、start_receipt）。可附 summary、metrics、receipts；核定历史评价时追加 supersedes。服务交叉核验项目、标题入口、PID、会话、截图 sidecar 与哈希；开发快照评分和合成夹具排除于正式轨迹。

生产评审提交后自动渲染该批 HTML/Markdown，并执行全量链接检查；失败可重试原请求。日常 progress 仅更新轻量快照。段落闭环和停机前可调用 render。兼容监视器只查看明确导出请求标记，避免每次 YAML、截图或音频更新触发全量扫描。
