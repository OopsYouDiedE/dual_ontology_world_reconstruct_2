## 新增独立评审

1. 独立 Terra 正常关闭自己的会话，将原始 on、新游戏 step、过程截图、指标与评审报告复制到本工程的 `artifacts/acceptance/`。
2. 为已观察段落建立 JSON 草稿，使用下列字段：
   - `schema_version: 1`、唯一 `id`、计划内 `segment_id`、实际 Git `revision`、带时区的 `observed_at`。
   - `reviewer` 写明独立 Terra 身份；`status` 为 `blocked`、`incomplete` 或 `complete`。
   - `scores` 按流畅度、字数、动作音效、响度、视听剧情替代、参考相似度、剧情流畅性排列七项。缺测写 `null`；`score_reasons` 对应七项原因。
   - `report` 是原始评审的项目相对路径。
   - `images` 保存实际截图的 `path`、完整 `sha256` 和可选 `caption`。
   - `source` 包含 `mode: real_mainline`、`entry: title_new_game`、原始 `session_id`、`on_receipt` 和 `start_receipt`。
   - 可选 `summary` 概述实际结果；`receipts` 保存该段更多原始输入回执的路径。
   - 可选 `metrics` 链接正常关闭后生成的 `segment-metrics.json`，HTML 会直接显示该段帧数、FPS、P95/P99 和尖峰。
3. 运行 `.runtime\python\Scripts\python.exe tools/testing/mainline_reviews.py --append 草稿.json`。可在同一次命令传入多个草稿批量导入。

导入器校验实际标题启动、同一主机的新游戏 R05 回执、项目/PID 来源、截图哈希、分数原因与本地文件。每条记录独占一个文件；相同内容可重复导入，修改旧记录时会报错。纠正评价使用新记录并说明原因。

评分记录稳定后，后台监视器自动批量转换 HTML/Markdown，并检查本地链接。原始材料保留原处，结构化导出位于 `artifacts/review/score_records.json`。

## 正式主线后台采集

正式输入 MCP 会话从标题开始自动采集，界面监控保持隐藏。observe 回执中的 `metrics_directory` 指向 `.runtime/mainline-runs/时间-PID/`，包含每帧 CSV、半秒 YAML 采样、实际混音 PCM、音频分析和最终 WAV。每项采样标明主线段落、房间、剧情时钟与字数豁免状态。

帧时间采用真实墙钟，包含加载、截图与采集开销；任一大于 33.3ms 的尖峰按用户标准记 6 分。未测音频、未试听的视听理解、未对照参考图的美学分继续待评。

正常关闭并归档后，运行 `.runtime\python\Scripts\python.exe tools/testing/mainline_metrics.py 归档指标目录`，自动按实际段落汇总 CSV/YAML，并从最终混音中只选择该段时段分析 LUFS 与真峰值，保留 FFmpeg 日志。`--incomplete` 仅供在测进度检查，产物明确标为 partial。监控记录当前可见书页、透明度、裁剪区与屏幕边界；旧版可见性采集存在误计时以实际截图复核，缺项保留待评。
