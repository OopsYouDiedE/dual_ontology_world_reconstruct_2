# 人物动作修复说明

本次将 `fix-model-animation-issues.zip` 内的动作补丁与工作区已有的剧情、角色动作修复合并。动画来源为 `assets/imported/kaykit/animations/` 的 KayKit Character Animations 1.1（CC0），角色外观继续使用 UserModels 的 Mixamo 骨骼模型。

## 问题与修复

| 现象 | 原因 | 合并后的行为 |
| --- | --- | --- |
| 移动时角色保持待机 | 手动移动设为 walk 后，同一帧的自动行走逻辑又设回 stand | 主循环保留手动行走状态；路径移动也驱动 walk |
| 开局躺姿变成坐姿 | 空路径分支按高度将人物设为 sit | 床上保持 lie；首次移动、调查或换房先起床 |
| 起床动作中途截断 | 固定等待 1.15 秒，Lie_StandUp 实际约 2.33 秒 | 等待姿态的真实播放时长；一次性片段结束后保持末帧 |
| 说话、工作定格，挥手缺失 | 持续姿态使用一次性片段，或缺少映射 | 补齐 talk、work_loop、lockpick_loop、wave 循环片段；保留单次 interact、operate、lockpick |
| 躺在床上悬空，起床后站进床里 | 骨骼片段内已包含床高与水平偏移，根节点又叠加床高 | 实测髋高、身体中心与床垫顶面；起床后半程平滑下降并移到床外可走位置 |
| 五人生活行动未显示对应动作 | Runtime 行动声明与 CharacterModel 播放链路未接通 | 快照传出 motor，按当前行动显示用餐、阅读、交谈、工作、坐卧；到场和结束时切换动画 |

## 实现与附件的合并

- `KayKitAnimationLibrary.gd` 使用 v3 缓存，逐一校验片段与循环模式；保留现有生活场景使用的 `work` 别名。
- `ProceduralFigure.gd` 使用 `POSE_CLIPS`、`clip_for_pose()`、`pose_length()` 统一映射与播放速度；对话、争执和指认在 Interact 循环上叠加原有手势，思考保留原有姿态。`measure_pose()` 测量人物局部坐标中的骨骼位置，并恢复测量前的播放状态。
- `DualWorldMain.gd` 从 Lowpoly 床垫网格读取床高与尺寸，按躺姿骨骼偏移放置人物。起床落点在床外，并优先投影到现有可行走网格。
- 附件的 React/Vite 页面用于展示说明；仓库中整理为本文、源代码与回归脚本。
- 原有 Terra 剧情修复随本次整理保留，包括推演重试、搜证门槛、知识解锁、存档隔离及读档暂停。

$Godot = '.runtime/godot/4.7.2/Godot_v4.7.2-stable_mono_win64_console.exe'

动作专测覆盖持续姿态映射、循环与逐帧保持、起床时长、床面接触和床外落点。跨入口动作回归覆盖骨骼随行走变化、手动移动完整主循环、路径移动、字幕手势，以及五人生活场景实际导航和到场动作。规则与界面脚本覆盖保留的剧情修复。

## 仍需画面与物理验收的部分

- 床面贴合使用髋骨到背部的估算厚度 `LIE_BACK_HALF_THICKNESS = 0.14` 米，可据实机画面微调；自动回归检查骨骼和网格数值。
- Lowpoly 房间与设计稿行走网格存在坐标偏移。起床落点沿用可走格校正，房间整体碰撞与坐标对位仍需后续处理。
- 对话、争执、指认、照料共用 Interact 动画源，通过速度和手势偏移区分；独立动作仍需更多素材。
- 五人生活坐卧已有动画播放，家具支撑、接触与身体碰撞仍需姿态驱动流程验收。
- 长时自动搜证与渲染画面验收独立于上述无界面动作回归。
- 本次界面冒烟与跨入口动作回归退出时分别报告 1 个、5 个 ObjectDB 对象残留；检查均通过，退出清理问题继续沿用 CHANGELOG 的 F9 跟踪。
