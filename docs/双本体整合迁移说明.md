# 双本体整合迁移说明（web 整合版 → Godot）

来源：`docs/archive/index-web-prototype.html`（web 整合版）、`docs/archive/refactor-project-to-web-game.zip`（UI／建筑器／角色模型原理展示）、`docs/archive/refactor-game-for-godot.zip`（五日剧情精简演示）。这些文件已从仓库根目录移入 `docs/archive/`（原路径已过期）。

目标：把 web 版里设计得好的部分搬回 Godot 项目。**只迁设计，不整包复制**：全部是纯 GDScript，不依赖 C# Core，因此不动 `core/`、`mcp/`、`tools/building_construction/` 与现有生活模拟入口。

## 迁了什么

| web 版的设计 | Godot 位置 | 说明 |
|---|---|---|
| 世界／房间／门锁（45 间、虚线连接） | `assets/data/dual_world/dual_world.json`、`DualData.gd` | 数据由 web 数据层导出为 JSON；房间 2D 地图坐标与 3D 真实尺寸分开存放 |
| **同词异义**（12 个词、17 人各自的义项） | `DualData.sense_of / sense_label`、`DualEngine.utter / conflict_senses` | 世界只记录行为，各人只保存自己的理解；字面为真（契约第八条）但义项不同 |
| **知识门槛**（九条源质知识） | `DualEngine.read_evidence` | 缺前置知识时证物只给「当前读法」；作者视角只改变显示，不替人物补知识 |
| 期待落空：只有一方申诉 | `DualEngine.resolve_conflict` | 关系账本写入单向申诉；第一天对质全错 → 三组关系永久受损，事后查明真相也不复原 |
| 推演先行：争执前必经的案卷推演 | `open_conflict → open_deduction` | 正解选项只有完成对应推演后才出现 |
| 五日节拍、四个结局 | `DualEngine.process_beats / compute_ending` | 有待决事项时时间冻结；确定性，可存读档（JSON） |
| **2D 完整场景地图** | `MapView2D.gd` | 房间间路径一律虚线（上锁为暗红）；点击、双击进入、平移缩放；暗幕随时间变化 |
| **3D 只显示单个房间** | `RoomMesh3D.gd` | 低多边形；地板、墙、门窗、家具、证物光柱由同一份设计生成 |
| **2D 可视化场景编辑器** | `BlueprintEditor2D.gd` | 真实尺寸蓝图：拖动／旋转／删除／撤销重做／吸附网格／门窗调整／实时校验；保存后 3D 直接使用 |
| 建筑结构生成器 | `RoomGeometry.gd` | 墙中线 → 内偏移地板 → 开洞不破坏闭环 → 家具有向占地（SAT）→ 自动布置与碰撞消解 |
| **防 z-fighting** | `RoomGeometry` 文件头、`RoomMesh3D` | 地板单张顶面；墙不生成底面与内部端面；地毯／挂画／护墙板／证物各自沿法线抬高 EPS；剖面隐藏前墙而不是半透明 |
| **昼夜与光线** | `DayNight.gd` | 太阳方位／色温、天空色、环境光、灯具亮度、夜间月光；2D 地图与编辑器用同一条暗幕曲线 |
| **程序化音乐** | `ProceduralScore.gd`、`GameAudio.gd` | `AudioStreamGenerator` 实时合成；调性／速度／织体随时间、对质、代管者显形而变；音效同源。`GameAudio.PROCEDURAL=true` 时不再读 `.ogg` |
| 程序化人物与姿态库 | `ProceduralFigure.gd` | 关节层级 + `RIG_SPEC` 姿态（stand/walk/sit/think/argue/point/talk…）；可选改用现有 `model_XX.glb` |
| UI（胡桃木／黄铜／案卷） | `DualWorldMain.gd` | 日志、证物、知识、词义对照、关系、契约、调试；词义分歧只有在「期待落空」后才显现 |

## 接入（对现有文件的最小改动）

- `scenes/UIpanel/TitleUI/TitleUI.tscn / .gd`：标题菜单新增「门的这一侧 · 双本体新局」，发出 `dual_world_requested`。
- `scenes/main/Main.gd`：`open_dual_world()` / `close_dual_world()`，进入时停止原配乐，返回时恢复标题曲。
- `scenes/components/shared/GameAudio.gd`：`PROCEDURAL` 开关，配乐与音效改走 `ProceduralScore`。

也可单独运行：`godot --path . res://scenes/dual_world/DualWorldMain.tscn`。

## 验证

```bash
godot --headless --path . --script res://tools/dual_world/dual_verify.gd   # 引擎规则 + 45 间房几何
godot --headless --path . --script res://tools/dual_world/dual_smoke.gd    # 界面、三种视图、3D 全房间、模态
```

`dual_verify.gd` 覆盖：同词异义（「救」「关门」）、缺知识只给当前读法、门锁与寻路、第一天对质全错 → 不可弥合且不会出现最佳结局、全部正解 + 九条知识 → 最佳结局、存读档往返、全部 45 间房的自动布置零越界／零重叠／开洞合法。

## 已知边界（如实说明）

- 以上脚本在 Godot 4.4.1 标准版无头模式下通过；**没有在 Godot .NET 4.7.2 编辑器里打开过**，也没有 GPU，所以 3D 画面与 2D 绘制只做了构建期与逻辑验证，**没有看过实际渲染**。首次打开请在编辑器里跑一遍并看一眼 3D 房间。
- 人物默认用程序化低多边形；`use_glb=true` 时只替换外观，不接骨骼动画（与迁移审查中「坐卧骨骼动画尚未接入」一致）。
- 剧情文本与 web 版相同，未与原 `campaign.dv` 逐条对账；Core 里的 DV 规则没有改动。
- 编辑器当前编辑单层单壳房间（与建筑器「首个封闭房间的单层」一致），不覆盖正式资源，设计存到 `user://dual_world/designs.json`。

## 界面与 3D 修正（正式游戏）

- 标题菜单：第一项「开始新游戏」= 双本体正式游戏；原「开始生活新局」改名「测试场景 · 生活推演」并移到后面。「继续游戏」读取最近的存档，正式游戏有自动存档（`user://dual_world/auto.json`，结局后删除）。
- 默认进入 3D 房间。**侦探是房间里一个带金色光环与名牌的人物**：换房间时先在旧房间里绕开家具走向通往目的地的门，出门后黑场，再从新房间对应的门走进来；点证物光柱或左侧证物按钮，侦探先走到跟前再查看。多段路程会提示「途经：…」。
- 台词逐句播放（点字幕可跳过）；台词播放和走路期间故事时间冻结，抉择／争执窗口在台词播完后才弹出，所以自动推进时也看得清发生了什么。
- 3D 取景自动放大到整间房刚好放进画面；视口占满整个窗口。
- 界面精简：顶栏只留时间、暂停／倍速、房间／地图、案卷、菜单；位置卡（房间、在场者、出口、本房证物）浮在左上，可折叠；日志／证物／知识／词义／关系／契约收进右侧「案卷」抽屉（默认收起，「调试」只在作者视角出现）；音乐、作者视角、存读档、编辑器、返回标题收进「菜单」。
- 脚本／测试可设 `instant_story = true` 恢复瞬时换房、不排台词的旧行为（`dual_smoke.gd` 使用）。

## 搜证门槛与自动搜证（修复：侦探无动作、无证据直接推理）

- 默认倍速由 ×20 改为 **×5**，倍速菜单新增 ×1 / ×2；读档时菜单跟随存档中的倍速。
- **搜证门槛**（`DualEngine._hold_for_evidence / gate_status`）：带推演的节拍到点时，侦探先被带到现场；手头相关证物不足 `minEvidence`（默认 2）时，这一拍不触发，**时间停在节拍上**，顶栏显示「等待搜证 · 推演名：证物 x/y　可查：房间」。证物够了才弹出推演。若再没有可取的证物（走不到），记一条「线索有限」后放行，避免卡死。作者视角不受门槛限制。
- **自动搜证**（顶栏「自动搜证」开关，默认开）：侦探空闲时自己走到证物前查看，先搜完所在房间；推演缺证物时自己换房间去取。关掉后完全由玩家点击证物。
- 测试：`dual_verify.gd` 增加门槛与诚实搜证机器人用例；`dual_autoplay.gd` 在真实时间、非 instant 模式下检查侦探确实在走动搜证。
