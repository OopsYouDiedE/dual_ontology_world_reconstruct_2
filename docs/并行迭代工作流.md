# 并行测试与性能基准

所有测试统一记录结果。每个片段一次提交七项分数、理由和证据；缺测项保留空值及原因。页面入口为 `artifacts/review/index.html`。

## 调度方式

一次 Godot 会话连续测试多个片段，复用启动、资源缓存与录音链路；会话结束后按片段汇总。这是当前第一天测试的默认方式。

性能采样期间只运行一个渲染实例，并暂停构建、其他引擎实例、音频后处理和批量图片导出。把这些作业安排在采样窗口之间。轻量调度和观察可以继续。功能测试允许并行，记录实际进程重叠与资源负载，保留每个实例自己的输出目录和 PID。

游戏启动、操作、观察和退出统一通过本项目 MCP。独立测试者 Terra 从固定提交开始，自主操作并关闭自己的会话；测试期间保持源代码固定。

## 并发观测与上限校准

输入会话及 evaluation 作业记录 `concurrency-observation.json`：每秒采样可见 Godot PID、系统 CPU 百分比与可用内存。采样遗漏、写盘失败和观测范围需与结果一起保留。进程计数只描述采样时观察到的负载；GPU 占用与极短重叠仍需额外测量。

当前尚无 1、2、3 实例的受控对照结果，因此安全实例上限保持未测。校准时固定提交、渲染器、分辨率、种子、场景、动作轨迹及采样时长，按 1→2→1→3→1 的顺序重复。每个实例独立排除同样的 1.5 秒加载预热，比较稳态 P95/P99、低帧率及超过 33.3 ms 的帧数，并保留全部原始数据。可预先把 P95/P99 增幅 10% 设为调查阈值；实际结论须结合重复试验波动及掉帧规则。

## 本次全天流程优化

共享主循环跳过隐藏 HUD 的字符串生成、隐藏地图重绘，以及隐藏侧栏按钮和日志的重建。打开地图或侧栏时使用当前状态刷新；回归检查覆盖隐藏控件身份保留、地图出口恢复、空日志刷新及实体书开关。

音频元数据保持逐条解析，实时指标写盘频率降至每 0.5 秒一次，结束时完整写入最终结果。655.74 秒旧录音的逐片段后处理复测耗时为 3.11、2.50、1.80 秒；本次未复现此前的 180 秒超时。该复测用于核对分析链路，当前版本的游戏评分由新的 Terra 会话产生。
