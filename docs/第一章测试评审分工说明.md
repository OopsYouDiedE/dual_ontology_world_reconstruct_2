# 第一章测试：观察员与主 Agent 的分工

本说明用于第一章的 11 个剧情分段测试。每个分段使用一个测试 ID；属于该分段的多个场景在同一实例、同一源码版本和连续采集时间线上完成。25 个场景是分段内的证据明细。

**观察员负责游玩和评审，自动采集器负责客观测量。主 Agent 在该段结束后将盲测剧情理解与标准剧情对照，并汇总发布。** 评审证据保存在同次测试中，其他评分由观察员与采集器完成，无须把原始采集数据交给主 Agent 重新评测。

游戏语言、观察员记录和技术证据使用英文。本说明以中文汇报分工。盲测观察员在完成剧情推测前不阅读剧情原文、标准答案或其他会泄露剧情的资料。

## 七项评分由谁负责

| 评分项 | 观察员与自动采集器负责 | 主 Agent 负责 |
| --- | --- | --- |
| `fluidity` 游戏流畅度 | 采集器记录逐帧时间、FPS、P95/P99、稳态卡顿和并发负载，并按量表计算。观察员补充自己察觉的卡顿和时间。冷启动和切场景后的前 1.5 秒单独记录。 | 接收同次测试的分数、理由和证据链接，发布。 |
| `text_density` 文字密度与英文 | 采集器逐帧检查文字状态并统计可见台词和交互提示；观察员对无法自动确定的文字用途和英文状态作标注。按照量表排除姓名牌和单键图标。 | 接收分数、理由和证据链接，发布。 |
| `action_sfx_integrity` 动作、贴花与音效 | 观察员在游玩中检查动作、接触、贴花、镜头和音效，记录缺陷、时间和证据，并按量表评分。采集器保留同次画面、录音和音效触发记录。 | 接收观察员的评分、理由和证据链接，发布。 |
| `audio_loudness` 音频响度 | 采集器从同次原始音频计算综合响度 LUFS 和真峰值 dBTP，并检查背景声、采集丢帧和音频路由。观察员可记录察觉到的声音异常。此项无须语音识别。 | 接收自动测量的分数、理由和证据链接，发布。 |
| `blind_narrative_match` 盲测剧情理解 | 盲测观察员边玩边用英文记录动作、对白、可感知的声音和自己对事件的原始理解；明确不确定之处。游玩结束后返回这些理解。 | 将观察员的原始理解与标准剧情逐项比较，说明对应、遗漏和误判，并给出本项评分。 |
| `aesthetic_similarity` 画面参考相似度 | 负责视觉评审的观察员在同次测试期间对照对应参考图，记录构图、光线、材质和可读性差异，并给分。如果参考图会泄露剧情，可由独立视觉观察员与盲测观察员分工，同时观察同一会话。 | 接收观察员的评分、理由和证据链接，发布。 |
| `narrative_flow` 叙事节奏与连贯性 | 观察员从玩家视角评估引导、等待、卡点和转场，记录理由及时间，并按量表评分。 | 接收观察员的评分、理由和证据链接，发布。 |

## 测试过程与回传

1. **主 Agent 在启动前组织。** 固定源码版本、测试 ID、分段和场景顺序；准备参考图及性能、文字、音频、画面采集，分配观察员，并确认观察员实际能接收画面、声音和视频的方式。向盲测观察员提供操作规则，不提供剧情答案。
2. **观察员在同一次会话中游玩并评审。** 通过项目 MCP 从分段入口操作，及时用英文记录关键动作、对白、剧情推测、声音、卡点和不确定之处；完成文字分类以及动作／音效、美术和节奏评审。自动采集器同步保留数据。多个场景按计划在同一实例中切换。
3. **该段结束后，只为剧情对照额外返回原始推测。** 盲测观察员把自己对剧情的理解交给主 Agent，主 Agent 与标准剧情比较并给出 `blind_narrative_match`。其他六项使用观察员已完成的评审或采集器的同次结算结果。
4. **主 Agent 汇总发布。** 使用同一个测试 ID 一次发布七项数值、各项理由、证据链接及具体失败或缺测原因。原始画面、视频、音频和测量文件留在该次测试的证据中，需要核查时可追溯；发布并不要求主 Agent 重做观察员的评审。不得从其他测试或版本借分；缺测留空，实测失败按证据给失败分。

## 视频、关键帧与逐帧数据

同一次测试应保留带时间戳的画面与原始音频，使其可以合成为同步视频，并与观察记录对应。视频供观察员检查完整过程；上传的接收端和实际评审方式应在启动前确定。当前项目 MCP 可返回画面和音频片段，观察员是否能够在其工具环境中播放或理解音频，需要在启动前实际确认。

剧情理解与参考图对照可以优先查看场景切换、交互、对白变化和剧情进展附近的关键帧；人物运动、镜头过渡与音效保留变化前后的连续片段。模型无须逐张阅读所有画面。性能仍逐帧记录时间；文字采集逐帧检查可见状态，只在状态变化时写入记录，以免遗漏短暂出现的提示。

视频、关键帧和指标都必须来自同一测试及时间线。测试期间需要完成的观察与评判同步进行；盲测理解与标准剧情的比较在该段游玩后进行。

## 当前进度

截至本说明编写时，本轮第一章尚未开始实际游玩，因此七项均没有本轮实测分数。代码已具备流畅度和响度的自动计算路径；文字项具备自动计数与观察员分类路径；其余四项依赖同次观察与剧情对照。视频导出和实际播放评审方式仍在准备，真实 Godot 会话中的采集和结算效果仍待验证。
