## 更新后的选择规则

按用户最新要求，本节优先于后文初步目录建议：按具体功能比较三个项目，确认新版覆盖原有行为且设计更合理时采用新版；否则以旧实现为功能基准，压缩重复代码后适配迁入目标。不按项目名、提交日期或代码行数直接判优，也不因目标有同名文件便认定已经替代来源功能。

## MCP、日志、图片和生成文件的统一规则

- 不迁移任何 `*.log`、`*.png`、`*.jpg`、`*.webp`、`output/**`、`artifacts/**`、`.runtime/**`、`.godot/**`。
- `.uid` 和 `.import` 是引用/导入配置，不是 `.godot` 缓存本体。它们随选定源资源逐项审查：保留必要稳定 UID、自定义导入脚本、骨骼/动画/材质导入参数；排除孤立、过期或仅默认自动生成的元数据。直接重新生成可能改变引用或模型行为。
- 按实际实例化方式选取 `.tscn` 与 `.gd`，保留场景实际使用的脚本；纯 `RefCounted` 工具不新增空场景。目标建造组件经 `ComponentFactory.script_path` 直接实例化 `.gd`，不恢复已经删除的 `.tscn` 包装层。来源项目的 1:1 约定不等于目标必须新增包装文件。
- 资产制作脚本、MCP 传输层和游戏运行时脚本分开审查；不能因为 Python 文件同名就覆盖目标协议。
