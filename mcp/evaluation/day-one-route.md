# 第一天剧情完整测试：连续路线与风险补测

## 两种记录，各有用途

**连续实玩是完整剧情的主记录。** 从正式标题页点击 New Game，使用真实的玩家输入，保留同一进程和存档，走到第一章结算，再显式继续到第二天。观察者自己选路；允许错过可选对话、返回房间、换行动顺序。记录玩家当时为什么选这条路、游戏给了什么反馈、是否还能继续。

**旧十一段与场景夹具保留为故障索引。** 它们适合复现厨房镜头、传声管、晚餐或章末的具体问题，也适合构造同一起点做成对比较。它们仍可使用原有历史评估入口；新版流程不拼接夹具结果来结算连续实玩。

## 一、开发与整合使用不同起点

剧情施工期默认从待改情节之前的最近检查点开始；按[剧情交接表](../../docs/development.md#按交接点检查)并行取证，每路至少尝试走出本节点，记录是否到达下一处可玩状态。跨节点验收使用上一段真实玩家进度形成的存档，复测时注明其来源；预设分支只验证分支结果。并行取证者使用 `close` 收尾并保留未评分观察；单一测试者负责判定。只有开场改变、存档兼容需要确认，或章节候选版需要端到端验收时，才从标题走完整日。

### 整合路线：一位测试者、一条时间线

1. 冻结已提交的修订，检查 Godot 4.7.2 .NET / .NET 8。由同一测试者操作、记证据和提交判定。若要验盲玩可读性，测试者在实玩前只读目标与操作说明，封存原文、路线攻略和参考图；先写下自己从游戏中理解的情节，再做对照。
2. 调用 `focus_open {"scope":"story","target":"day-one-live","tester":"<姓名>"}`。这是实机连续路线开发入口：正式标题、独立存档与设置，默认启用听证。用当前画面的 `New Game` 进入；中途保持同一 `session_id`，不用检查点、重开、`next_case` 或直接调用处理器。
3. 行动选择遵从实际可用的门、线索和提示。受剧情控制的开场检查引导与控制权何时交还；进入自由调查后记录自主选择、门槛提示、返回或延后的结果；晚间核对本次行动留下的状态如何收束。每次关键动作前后记游戏时间、房间、目的、可见提示和实际结果。关键路线变化可用 `focus_step` 的 `note` 补记；工具另把观测到的房间、时间、已发现数量、门槛或选择状态写入 HTML 时间线。中间没观测到的路径保留为空白。
4. 看到第一章完成界面时先记录一步；再选择继续，记录 `Day 2 / R05 / Chapter 2`。引擎的第一章结算还依赖 **22:00、晚间分工已落实、待处理门槛和选择已清空**。路上遇到卡点，记录最后可用动作、阻塞状态和恢复尝试。存档持久性如需关进程回读，另开独立复查，并标记关联路线；保留首次实玩原始结果。
5. 调用 `focus_finish` 提交四项：`completion`（从正式开局到结算并继续）、`agency`（可选行动及受限时的反馈与恢复）、`state_continuity`（时间、房间、线索和待办的跨场景连续性）、`presentation`（对话、镜头、动作与关键声响提供的信息）。通过或失败引用观察步骤。完成项通过要求同一时间线先观察到第一章完成，再观察到第二天抵达 R05；卡住写失败或受阻。静态只截关键状态；表演、交接或镜头跳变用分帧；关键声音按需留 WAV。

## 二、补测优先验证不同选择会对状态产生什么影响

| 覆盖风险 | 走法 | 对照的结果 |
|---|---|---|
| 合法顺序交换 | 从同一真实检查点出发；若两个目标都已开放，做 A→B 和 B→A | 两次分别记录当时开放情况、知识和提示、最终可达的关键节点，以及顺序原本就应造成的差异 |
| 延后、绕路、回访 | 离开一项尚未处理的调查，进行另一项可达行动，再回来 | 时间和人物活动继续变化；已获得信息保持，待办可识别且有回收路径；注明是否遇到设计中的时限 |
| 选择分歧 | 从同一选择前状态复测尚未走过的选项，例如黑板诗 | 每条分支记录自己的线索、对白与后续结果；已走分支的成绩不代填其他分支 |
| 门槛与解锁 | 在明确欠缺前置条件时试一次，满足条件后重试 | 初次阻挡给出可读的理由或下一步线索；条件满足后同一个入口可用 |

优先补主路线实际遇见的风险，以及覆盖表里完全未触达的关键分支。一次全日通关加有针对性的短复测，通常比按十一段逐段重放更容易发现时间、道具与选择跨房失效的问题。只有替代顺序本身跨越很长的时间链、短复测无法验证时，再跑第二条全日路线。夹具或同源检查点都要保留来源，并独立记录结果。

## 三、发布与运行授权

[实时 HTML](../../artifacts/review/focused.html) 以 `day-one-live` 显示连续观测轨迹和四项判定。新方案保留有用途的帧时间、文字、音频与参考对照作为诊断证据；不以单帧卡顿、字数或旧十一段均分替代试玩结论。需要量化时写清采样范围与缺测原因。`day-one-live` 当前发布**开发实玩结果**；正式验收遵循项目现有独立证据、冻结修订与运行窗口约束。`goal.md` 只在用户明确授权后更新。
