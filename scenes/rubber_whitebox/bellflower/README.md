# 03 / The Bellflower — 可执行样板 v1

03 是独立的双人白模场景。队友在入口受保护的右道等候；队长走到标记线后接引。两条导道沿纵轴约束行走，两人各自逐步移动。右道踏板机械抬升两口低钟；回程闩的保持时长随松板瞬间的凸轮位置变化。队长先过，到远侧回望，用亮处两口低钟的近距命中证明左钟正上行，并给踏板员一次离板窗口。

## 运行

从仓库根目录运行，Python 3.10+ 只用标准库。Godot 运行时使用项目的 Godot 4.7.2 .NET。

```powershell
$scene = 'res://scenes/rubber_whitebox/bellflower/Bellflower.tscn'
$godot = '.runtime/godot/4.7.2/Godot_v4.7.2-stable_mono_win64_console.exe'
& $godot --path . --rendering-method forward_plus $scene -- "--python=$((Get-Command python).Source)" --seed=1
python scenes/rubber_whitebox/bellflower/verify.py
& scenes/rubber_whitebox/bellflower/capture.ps1 -Seed 1
```

- **W/S** 队长前后；**↑/↓** 队友前后；**Q/E** 转身；**PgUp/PgDn** 只调画面仰角；**F** 接引；**P** 提交当前能组成的射线证明；**T** 重开并切换 B4 自动回放；**R** 重开。
- **V** 显示最近一次 3 Hz 的 27 条射线及 3×9 命中格。亮命中、暗处拒读、落空分别标记。暗处截止点只出现在美术诊断层，参赛输入仍为 `null`。
- **H** 移除装置：同一帧切掉可见实体、碰撞、遮光和规则联锁。该局标为诊断局；用 **R** 回到正常样板。
- `--strong` 选强种子包；`--auto` 一启动就跑 B4；`--headless ... -- --smoke` 跑完自动退出。
- 截图脚本用真实 Forward+ 导出 A 大厅剖面、B 入口眼高、C 低钟夹隙和 D 实际扫描叠层，写入 `.runtime/bellflower/review/`。四图使用同一机关姿态。
- 项目游戏 MCP 的 `on(scene="bellflower")` 支持 `bellflower_rays`、`bellflower_remove`、`bellflower_reference`、`bellflower_reset`；旧的 MCP 客户端刷新工具表后可选此场景。

## 同源与裁判边界

| 文件 | 职责 |
|---|---|
| `arena.json` | 房间、双导道、机关尺寸、阵列花冠、灯、两档随机范围、快照机位、原生 AST 与局部豁免。内部长度整数用毫米，观测用微米和微度。 |
| `bellflower.py` | 单一执行源。构造凸体及位姿、60 Hz 状态推进、扫掠、裁判聚光锥与实体遮挡、3×9 扫描、三值 AST、证据核验及心智状态。 |
| `bridge.py` | Python 常驻进程；Godot 以 JSONL 读取初始凸体和每次单物理步更新。限人工/参考控制；预览和移除属于诊断。 |
| `Bellflower.gd` | 用同一凸体顶点构造可见三角面与 Godot 凸碰撞体，并用同位姿投 Forward+ 阴影。审美光色/曝光与裁判照度分列。 |
| `verify.py` | 全种子采样检查、严格规则的可达性证明、见证回放、计时与 B0–B4 消融。无需启动 Godot。 |

大厅为 18.4 × 21.8 m，净高 13.2 m。中轴花冠由落地双柱和跨越中央导道的铸铁横梁承托。下层轴心 3.29 m，上下各五只黑色轴座，每座带动两根错相、同轴转动的半圈螺旋管。管径从根部的 496 mm 收至末端的 372 mm；下层管尖外展下垂，钟槌在完整摆动包络中仍留约 80 mm 离地净空。吊绳跟随末端并保持竖直。下方两口直径 0.98 m 的低钟通过横梁和升降导向悬挂，钟身及钟槌承担碰撞、遮光和取证。其凸体下缘与人体体积做连续步内扫掠。踏板触发要求脚底投影完整落在踏面内。原册是**进门前确认全开；踏板员留在板上直到全员过门**。可放宽的是第二条。队长到远侧且闩仍保持时，已授予的证据许可可用于一次**开始向前离板**；迟一步仍可能撞上下降的实钟。铃声在升起的凸轮进入撞铃相位时响起，AI 通过钟身位移读出相位。

本样板使用平地导道的确定性运动学。渲染、截图和诊断预置独立于竞技步骤；Godot 通用刚体求解器不参与成绩。整个入口到出口可用离散正反走、转头、等候和举证完成。

## 体检口径

- 默认固定母种 `3103` 生成普通/强档各 10 种；更换用 `--master-seed N`。`--quick` 只跑 B4 与结构检查。体检单写 `.runtime/bellflower/report.json`；程序失败返回非零。
- **漏扫**：从 1.65 m 眼高的安全观测点，在锁定全开以及未抬升两个工况里，枚举一个完整周期和全部 20 种扫描起始相位。检测到两口实体钟并判对“撞铃相位”或“双钟低位夹角”方为成功。开合中间态允许输出 `other`。
- **证明**：先检查连续转动包络的离地净空及导道侧向净空；再用向前、后退、等待的区域可达性过近似检查两种单人角色和两人全守。严格手册下不存在首次合法离板，回程窗因此不可达；双钟全抬时连续扫掠净空为正。放宽路径单独回放实际逐步输入和原始射线地址。
- **消融**：B0 只往前；B2 贪心分工，见首个合格证明就离板；B3 分别改用单帧阈值、移除举证、撤掉“队长过门回望／踏板员等候”的协同；B4 在射线观测上估计凸轮上行斜率，选择许可内的离板步。各组读同一私有后端导出的观测、队长本体读数和公开手册；无种子、实际闩剩余时间或全队坐标。
- **预算与余量**：试验观察窗 1,440 步；场景本身沿用 36,000 步硬预算。每步 20 ms、对齐的每 20 步 100 ms。默认计单线程 CPU 算力，逐例同时记录墙钟峰值；`--timing wall` 改用严格墙钟。末位余量是从队友扫掠出闸到其通道恢复致死压低位置的物理步数。
