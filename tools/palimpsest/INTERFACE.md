# A03 scene integration contract — The Palimpsest Switchyard

Preload `res://scenes/physics_lab/palimpsest/PalimpsestRules.gd` and `.new()` it. Pure `RefCounted`; no scene, InputMap, wall clock, RNG, save data, or node dependencies. One model per attempt.

- `board() -> Dictionary`: `width`, `height`, `start`, `lift_start`, `turn`, `exit`, `hold`, `bays`. Each bay has `id`, `x`, `y`, `ink` and `lift` (three destination IDs each). The board is 9 columns × 8 rows, with row-major bay IDs 0–71; `start` is 0 (NW) and `lift_start` is 71 (SE). Reserve `turn = -1`, `exit = -2`, `hold = -3`; a `hold` socket is capped. A directed rail terminates at the named destination. Render the ink/lift decks directly from these arrays. Socket indices 0, 1, 2 display as I, II, III.
- `snapshot() -> Dictionary`: `tick`, `phase` (`record`, `rewind`, `won`, `failed`), `ink_bay`, `lift_bay`, `pins` (-1 blank, 0..2 set), `cured` (bool per bay), `tape` (socket indices in recording order), `cursor` (next rewind index, -1 when absent), `pending` (action string or empty), `in_flight` (route descriptor or empty), `failure` (reason code or empty), `event` (most recent completed transition), `actions` (array of queueable action strings). Snapshots and board data are detached copies.
- `preview(action: String) -> Dictionary`: pure, returns `ok`, `reason`, `action`, `base_tick`, `horizon_ticks`, `frames` (one full snapshot per simulated tick, offsets 1..40). A legal commit can forecast a crash; inspect `frames[19]` and `frames[39]` for the main ghost endpoints, and `in_flight` for the rails. Record forecasts dwell after the proposed move; a rewind forecast shows two actual return strokes. Terminal forecasts hold their endpoint. Invalid actions give an empty frame array.
- `submit(action: String) -> bool`: queues only at a 20-tick boundary. Actions are `port_0`, `port_1`, `port_2`, `rewind`. A capped socket is unavailable. The presentation should show `preview(action)` in-world before the player confirms any queued move; preview and live share the same transitions. Suggested bindings: `1/2/3` select a socket, `E` confirms a preview (at the Turn, selects/confirms Rewind), `R` restarts at a quiet boundary by replacing the model. No free-roam input feeds authority.
- `step_tick() -> bool`: call once per 60 Hz physics tick. Returns whether time advanced. Idle planning and terminal state pause the simulation. A commit travels for 20 ticks; at the boundary it updates occupancy and pins. Rewind drives the lift cart automatically until win/fail; the scene needs no extra input to advance it. When no action is queued, the scene can redraw directly from the most recent snapshot.
- `in_flight`/`event` route fields: `deck`, `from`, `to`, `port`, `pulse`, `pin`, `tape_index` (unused values use -1); Both include `start_tick` and `end_tick`; `event` adds `code`. Alpha = `(snapshot.tick - start_tick) / 20.0` for rendering only.

## Mechanism

Every ink departure sets its bay's pin to the chosen socket and records the same socket on the tape. Pins latch for the attempt; trying to cross a previously set bay jams the cart. The Turn is beyond the far bay; reaching it before all bays are stamped fails its interlock. Rewind launches the lift at that same far bay. Each lift stroke reads the next tape entry backward, mirrors it (`2 - pulse`), and rotates the local gate by its ink pin (`(2 - pulse + pin) % 3`). Crossing that gate cures its pin permanently. The lift must cure every bay and then take the rail into the Exit. Returning through a cured bay, hitting a capped return socket, or using the Exit early ends the attempt. No rewinds of the ink pass, no editing the tape, no direct lift steering.

Rails run between adjacent bays, including diagonals, or into the two terminal docks. Read the board data rather than hardcoding dimensions or rails. A scene can show the lift's three rails at every bay before recording begins, and after pinning it can show the resulting pulse-to-rail mapping (always three known outcomes). A two-stroke ghost is the default preview; terminal failures may be drawn as red endpoints instead of hiding the legal risky action.

## Feedback codes

- Completed transitions: `ink_stamped`, `turn_ready`, `lift_cured`, `exit_open`. These appear in `event.code`.
- Attempt failures: `ink_revisit`, `turn_incomplete`, `lift_revisit`, `lift_capped`, `early_exit`. These appear in both `failure` and `event.code`. `tape_spent` is a defensive guard if the board and tape capacity diverge. A capped lift stroke reports `event.to == hold`; the cart and uncured pin remain at `event.from`.
- Rejected requests: `unknown_action`, `terminal`, `rewind_automatic`, `busy`, `turn_only`, `need_turn`, `capped_socket`. These are `preview().reason`; rejection leaves authority unchanged. `preview().ok` means queueable, so use the returned failure state to color a forecast.
